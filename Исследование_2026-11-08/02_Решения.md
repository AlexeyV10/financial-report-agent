# Пересмотр прежних решений

Дата: 08.11.2026. Старые предложения — из архивов переноса и плана, а не автоматически требования курса; новое — рекомендация, пока не решение команды.

| Вопрос | Что предлагалось раньше | Насколько обосновано | Изменение / проверка |
|---|---|---|---|
| Рынок | SEC и США в первоначальном плане; поздний перенос не выбирал рынок | Устарело по новому указанию | Российские публичные компании и источники; SEC только для сравнений. |
| Статус | Идея и материалы КП1 | Пользователь подтвердил отсутствие последующей реализации | Не выдавать архитектуру, метрики и планы за выполненные результаты. Статус сдачи КП2 неизвестен. |
| Аудитория | Аналитик небольшой инвесткоманды | Возможная аудитория, интервью нет | Сохранить как персону-гипотезу, дополнить корпоративными финансами; проверить 3–5 беседами, не обещая коммерческий пилот. |
| Источники | EDGAR, XBRL, 10-K/10-Q | Непригодно как базовый российский конвейер | Документы эмитента, раскрытие, ручная сверка; ISS только для разрешённых сценариев цен. |
| Показатели | Выручка, рост, маржа, поток, FCF | Полезно для нефинансовых компаний, но не универсально | Утвердить отраслевой словарь; для финорганизаций начать с подходящих строк, не смешивать доход и выручку. |
| Агент | Агентный RAG с узкими инструментами | Соответствует теме, польза не измерена | Один ограниченный агент + фиксированный рабочий процесс как контроль. |
| Поиск | FTS5, далее векторный | Разумный бюджетный старт, русская морфология не проверена | Замерить recall@k по страницам; векторный/гибридный только при подтверждённых ошибках. |
| PDF | В плане был преимущественно структурированный XBRL | Российские PDF сложнее, извлечение ненадёжно | Сохранять страницу, таблицу, заголовки; факты первых документов вручную подтверждать. |
| Симулятор | Условные сделки, point-in-time, расходы | Важен для названия, но права и время существенно усложняют | Сначала синтетическая событийная модель и ручная сверка; реальные цены после проверки прав. |
| Оценка | 60 вопросов, 80/90% цели | Планируемые ориентиры, не требование и не результат | Составить посильный набор, фиксировать размеры, категории и парные ошибки; не утаивать слабые результаты. |
| Технологии | Python 3.12, SQLite, Streamlit, FastAPI | Разумно, но обязательность API преждевременна | Python + SQLite + Streamlit; FastAPI по потребности, модель взаимозаменяема. |
| Сроки | КП2 5 ноября, КП3 15 декабря | Только копия курса, часовой пояс не указан | КП2 прошёл; выяснить статус. Не выдумывать перенос. План по оставшемуся времени в отдельном файле. |

## Развилки и критерии возврата

| Развилка | Варианты, стоимость и риск | Рекомендация; когда вернуться к другому варианту; проверка |
|---|---|---|
| Данные | Структурированные таблицы быстры, но не обязательно воспроизводят версию и покрывают нужные показатели; PDF/HTML чаще содержат первоисточник, но сложны в разборе. | PDF + ручной подтверждённый слой фактов, XLSX только со сверкой. Добавить API, когда подтверждены охват, даты и права. Тест: 10 ячеек с ручной проверкой. |
| Поиск | FTS простой и быстрый; векторная модель требует памяти/загрузки, гибрид сложнее в настройке. | FTS + фильтры; вернуть гибрид, если разметка показывает пропуски синонимов. Проверить recall@5 на одинаковых запросах и страницах. |
| Управление | RAG один проход дёшев; фиксированный процесс проверяем; агент гибок, но может зациклиться; несколько агентов повышают сложность и цену. | Фиксированный процесс и один ограниченный агент; несколько агентов лишь после демонстрации конкретной прибавки на dev. Сравнить один и тот же набор. |
| Инструменты | Чистый Python понятен новичкам; фреймворк оркестрации даёт готовые трассы, но добавляет зависимости и обучение. | Python и явный журнал вызовов; LangGraph рассмотреть, когда ветвления трудно поддерживать и команда понимает трассу. Измерить время до воспроизводимого теста. |
| Модель | Облако удобно на 16 ГБ, но расходы/доступ и внешняя передача; локальная модель зависит от памяти и качества русского. | Настраиваемый интерфейс и mock, затем доступная облачная или локальная после мини-оценки; сравнить качество, память, время и цену, не называть победителя заранее. |
| Хранение | Файлы + SQLite просты и воспроизводимы; серверная БД и векторное хранилище масштабируются, но сложнее в эксплуатации. | SQLite, PDF отдельно, хеш и локаторы; переход при измеренном объёме/совместном доступе. Проверить восстановление на чистой машине. |
| Симуляция | Самописный узкий код прозрачен и дешевле для обучения, но разработчики отвечают за крайние случаи; LEAN/другая библиотека дают инфраструктуру, но требуют освоения и проверки лицензий. | Малый симулятор на синтетике с независимым ручным эталоном; библиотека при необходимости портфеля и подтверждённом времени на интеграцию. |
| Интерфейс | Streamlit быстрый для демонстрации; отдельный frontend/API гибче, но больше интеграции; CLI быстрее всего. | CLI для ранней проверки, затем Streamlit; FastAPI — если реально нужен отдельный клиент. Проверка: другой участник воспроизводит путь с чистого запуска. |

Все сравнения качества, цены и времени пока ожидаемые последствия выбора, а не измерения. Границы проекта и его название сохраняются.
