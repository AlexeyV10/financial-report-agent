# Выступление и демонстрация КП2

Рабочая версия от 09.11.2026 для пяти слайдов KP2_slides_v2.pptx. Примерно две минуты — допущение для компактного рассказа, не подтверждённый текущий регламент. В исторической копии курса: 05.11.2026 12:00 и 2+1 минуты; эта дата уже прошла. Действующие условия и факт сдачи неизвестны.

Основной текст содержит 228 слов при подсчёте по пробелам. Оценка кодом: при 120–140 словах в минуту и 10–15 секундах на переходы получается 108–129 секунд; при 130 словах в минуту и 15 секундах пауз — около 120 секунд. Это расчёт, не запись выступления пользователя. Говорить естественно; демонстрация ниже — дополнительный резерв, её длительность не включена в эти две минуты.

Те же пять абзацев внесены в заметки соответствующих слайдов. Источники утверждений также указаны в заметках и разделе «Проверяемые артефакты» отчёта.

## Слайд 1. Что подготовлено

Наш проект помогает проверять финансовый ответ по источнику. К этой контрольной точке подготовлены локальный прототип, первые измерения и архив, который мы восстановили в новой папке. Фактически работу выполняем я и Codex.

## Слайд 2. Как получается ответ

Пользователь выбирает компанию, показатель и годы. Поиск находит место в документе, затем код связывает его с ручной разметкой, проверяет контекст и считает формулу. В варианте B порядок фиксирован. В C настоящая локальная модель выбирает разрешённые инструменты. Произвольный русский вопрос пока не поддерживается.

## Слайд 3. Что показал малый замер

Здесь один числовой вопрос и два случая для отказа, все открытые и на одном документе. Числовой ответ верен у обоих вариантов. B правильно отказал в двух случаях, C только в одном. При поиске top1 агент получил отказ калькулятора на шестом решении, но не успел завершить ответ. Поэтому это ошибка, даже без выдуманного числа. Поддержаны три из десяти подготовленных финансовых вопросов.

## Слайд 4. Вымышленный сценарий и восстановление

Торговую часть проверяем отдельно на полностью вымышленных ценах и датах. Из десяти тысяч после покупки и продажи с комиссиями получается десять тысяч девяносто восемь рублей. Удержание той же доли даёт тот же итог. Это проверка арифметики. Архив также распакован и запущен в отдельной среде, прошли двести шестьдесят семь тестов кода.

## Слайд 5. Ограничения и следующий результат

Сейчас есть один показатель и отдельный искусственный сценарий. Дата публикации реальной PDF-версии неизвестна, поэтому исторический расчёт и реальные сделки заблокированы. Дальше нужны новые проверенные источники, расширение поддержанных задач и исправление завершения отказов. Общего качества модели и пользы для бизнеса этот малый замер пока не доказывает.

## Демонстрация, если для неё есть время

Запускать из корня рабочей или восстановленной копии. Полная инструкция восстановления и зависимостей — docs/local_demo.md в техническом архиве. Никакого нового запуска LLM для этой подготовки не требуется. Все команды ниже работают без модели; первая явно использует ручную разметку, без нового поиска или сверки PDF.

1. **Проверяемый ответ, около 15 секунд.** Выполнить:

~~~powershell
python -I scripts/run_local.py fixed --source manual
~~~

Показать группу «ФосАгро», МСФО, полные 2023/2024 годы, 440304/507689 млн RUB, разность +67385 и рост +15,30%. Обратить внимание на формулу и локаторы PDF4 слева / печатная320 / строка «Выручка», а также на неизвестную публикацию выбранной версии. Значение2023 — сравнительная колонка версии2024. Числа из ручной разметки и кодового расчёта; модель здесь не используется.

2. **Ограничение на настоящем источнике, около 10 секунд.** Выполнить:

~~~powershell
python -I scripts/run_local.py scenario --case real-source
~~~

Показать blocked/publication_unknown: нет сделок и доходности. Подпись отчёта не доказывает дату публикации этой PDF-версии.

3. **Отдельная вымышленная арифметика, около 10 секунд.** Выполнить:

~~~powershell
python -I scripts/run_local.py scenario
~~~

Показать пометку искусственного примера: капитал10000 → покупка20×100 с комиссией1 → cash7999 → продажа20×105 с комиссией1 → итог10098 RUB, +0,98%, расходов2. Те же цены и расходы для удержания дали тот же итог. Это вымышленные входы, а не рыночный результат.

Все три команды технически проверены при подготовке материалов; выводы и коды выхода сохранены в evaluation/step14_2026-11-09/demo-rehearsal/. Указанные 15/10/10 секунд — ориентиры показа, не измерение речи или действий пользователя. Полный запуск/чтение вывода может занять больше времени.

## Резерв для вопроса об агенте

Открыть локальные сохранённые результаты шага12: evaluation/step12_2026-11-09/run-02-environment-retry/results.json, raw и trace в той же папке. Это запись прежнего запуска настоящей Qwen3 4B, не текущий живой ответ. Показать QA03: 5 решений, answered; затем QA07: 6 решений, limit_exceeded / error / call_limit. Калькулятор уже вернул missing, но модель не успела выполнить finish. Ошибка сохранена и не превращена в корректный отказ.

Не запускать заново всю модельную оценку ради защиты и не подставлять mock. Если нужна именно живая LLM-демонстрация, это отдельный разрешённый запуск прежнего pinned loopback-сервера по docs/local_demo.md с сохранением trace и остановкой только своего owner PID. Веса и PDF в технический архив не включены; установка модели на другом ПК не проверена. Необязательный явный agent --adapter mock демонстрирует только протокол, его нельзя выдавать за ИИ.

## Короткие ответы на вопросы

**Что делает ИИ?** Выбирает один из четырёх разрешённых инструментов по наблюдениям. Числа, формулу и итоговый текст проверяет и формирует код. Понимание любого русского вопроса пока не реализовано.

**Зачем B?** Это фиксированный порядок тех же инструментов для сравнения. На текущем малом открытом наборе C преимущества не показал.

**Насколько точна модель?** Пока один числовой dev-вопрос: B/C 1/1; два случая для отказа: B2/2, C1/2. Поддержаны3/10 финансовых записей. Четыре числовых утверждения относятся к одному ответу, а не к четырём независимым вопросам. Резервные финансовые задачи B/C не измерены, n=0.

**Это автоматическое извлечение фактов из любого PDF?** Нет. Поиск выдаёт кандидатов; числа связаны с прежними вручную размеченными и проверенными Codex фактами одной версии документа. Ссылка сама по себе число не доказывает.

**Можно торговать по результату?** Настоящий источник заблокирован: публикация именно этой PDF-версии не доказана. В симуляторе отдельные вымышленные цены, даты и заранее заданное правило. Это проверка арифметики, не совет и не обещание доходности.

**Что означают 267 тестов?** Проверки кода, успешно выполненные из новой копии на шаге13. Они не дают267 дополнительных вопросов качества ИИ. На шаге14 весь этот прогон не повторяли.

**Кто сделал проект?** Пользователь принимал решения и разрешал действия; Codex реализовал код, подготовил ручную разметку и искусственные данные, выполнил сверки, расчёты, тесты, измерения и эти материалы. Пять именных ролей — только оформление регламента; чужую работу или независимую человеческую проверку не заявляем.

**Сколько стоит?** Платный API не использовался; модель локальная. Шаг12:17 реальных chat,39000 входных/849 выходных токенов. Общая стоимость оборудования и электричества не измерена, cost=null. Интеграционный запуск шага13 не прибавляется к знаменателю шага12.

**Что дальше?** Сначала актуальные реквизиты сдачи и подтверждение отправки; технически — новые проверенные источники, новые поддержанные задачи, отдельная независимая оценка и завершение отказов C. Новую готовность не выдавать за уже выполненную работу.
