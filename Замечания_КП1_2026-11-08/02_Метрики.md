# Численные метрики: полная рабочая спецификация

08.11.2026. Никаких результатов измерений пока нет. Ниже — предлагаемый протокол, учебные числа вымышлены. Метрики качества оценивают программу; финансовые показатели описывают компанию; показатели симуляции описывают условный эксперимент. Нельзя выводить одно из другого.

## Общие правила оценивания

Единица наблюдения задаётся каждой метрикой: вопрос, утверждение, поиск или проверка сценария. Значение `0/0` — **не измерено**, а не 0% и не 100%. Сбой модели и таймаут включать в знаменатель задач, для которых запланирован запуск, и показывать отдельно; не отбрасывать неудобные случаи. Если экспертом не установлен эталон, случай маркировать `unscorable`, раскрывать число и причину, исключать только из соответствующей метрики по заранее зафиксированному правилу. Частично верный ответ в строгой итоговой метрике считается ошибкой; для диагностики отдельно сохранять правильность каждого поля. Не заменять полным баллом наличие части верного ответа.

Числа сравниваются после разрешённого преобразования масштаба и валюты без конвертации по курсу. Например 1,2 млрд руб. равно 1 200 млн руб.; 1 200 тыс. руб. не равно 1 200 млн. Эталон хранит абсолютный допуск `a` и относительный `r` в зависимости от точности исходного документа; правило `|x−y| ≤ max(a,r×|y|)`, если заранее утверждено. Для нуля используется абсолютный допуск; не вводить общий процент задним числом. Округление отдельно хранить и показывать.

## 1. Качество ассистента

Во всех примерах ниже числитель и знаменатель вымышлены. Эксперт проверяет по первичному документу, а не по ответу модели. Более точное объяснение одинаково важно, как и формула.

### 1.1 Строгая точность финансового факта

- **Что:** доля ответимых численных вопросов, в которых одновременно верны значение с допуском, показатель, компания/группа, стандарт, период, валюта, масштаб и допустимая версия на as-of.
- **Формула:** `correct_fact_questions / answerable_numeric_questions`. Единица — вопрос. Отказ, отсутствующий атрибут, недопустимая версия и неправильная ссылка на факт означают 0 по строгому критерию; отдельно можно оценивать ссылки по 1.3. Для вопроса с несколькими обязательными фактами верны все.
- **Пример:** 8 правильных из 10 → 8/10 = 80%; 1 из двух чисел правильное на одном вопросе — по строгой метрике 0, в диагностике два поля 1/2.
- **Нужно:** эталон и точный документ с периодом, единицей, диапазоном округления, as-of и версиями; разметчик и независимый проверяющий. Ограничение: достаточно корректный численный ответ без объяснения ещё не делает источник доказанным.

### 1.2 Поиск доказательств: Hit@5 и Recall@5

- **Что:** Hit@5 — доля размеченных поисковых запросов, где в первых пяти найден хотя бы один допустимый релевантный фрагмент; Recall@5 — доля найденных в первых пяти обязательных эталонных фрагментов, усреднённая по запросам. Если для ответа нужны две таблицы, попадания в одну для Hit недостаточно как доказательства полной поддержки, потому отдельно считать Recall и полноту.
- **Формулы:** `Hit@5 = Σ I(число найденных релевантных > 0)/N`; `Recall@5 = (1/N) Σ |retrieved_5 ∩ gold_i|/|gold_i|`. Единица — запрос; идентичность по документу, версии и диапазону/ячейке. Для N брать только запросы с известным непустым gold; число исключённых и запросы без данных сообщать отдельно. Разбивка на фрагменты не должна позволять дубликатам раздуть счётчик.
- **Пример:** в 3 запросах gold размера 2, 1, 1 найдено соответственно 1, 1, 0 → Hit=2/3=66,7%, Recall=(1/2+1+0)/3=50%.
- **Нужно:** эталонные локаторы, ранжированный список и индекс; Марк размечает, Тимофей сверяет. Неполный список допустимых источников может несправедливо наказать найденный альтернативный источник; эксперт добавляет его по заранее установленным правилам до анализа результатов.

### 1.3 Подтверждённость утверждений

- **Что и формула:** `подтверждённые существенные утверждения / все существенные проверяемые утверждения`. Единица — утверждение, а не ответ. Поддержано только если указанный фрагмент подтверждает смысл, сущность, число, период и версию; ссылка, которая лишь открывается, не достаточна. Отсутствие ссылки = неподтверждённое утверждение.
- **Пример:** 7 из 8 утверждений подтверждены → 87,5%; восьмое без источника остаётся в знаменателе. Нет проверяемых утверждений в корректном отказе → показатель для этого ответа неприменим; отдельно сообщить долю ответов без утверждений и качество отказов.
- **Данные и проверка:** список атомарных утверждений и evidence_id, два независимых проверяющих; спор решается по документу. Нельзя считать отказ лучшим ответом лишь потому, что утверждений нет.

### 1.4 Формула, входы и результат

- **Что:** строгая правильность вычисления на задачах, где ответ требует расчёта: правильно выбраны все входы, операция и порядок, период и единицы, выполнено вычисление и указана единица результата. `correct_calculations / all_answerable_calculation_questions`; единица — вопрос. Отказы, неверный факт и неверная формула — ошибки. Отдельно диагностировать `correct_formula / all_answerable_calculation_questions` и результат при подаче эталонных входов, чтобы локализовать ошибку, не подменяя сквозной метрики.
- **Пример:** 6 из 8 расчётов полностью верны → 75%; ещё один с правильной формулой и неправильным входом не получает полный балл.
- **Нужно:** эталонные факты, формула или множество математически эквивалентных формул, ожидаемый результат и допуск. Тимофей вычисляет вручную, Владимир проверяет код. Равный итог случайно не доказывает правильную формулу.

### 1.5 Отказы и ответы при нехватке данных

- **Что:** `правильные обоснованные отказы / вопросы с недостаточными данными` — доля корректных отказов; `ошибочные отказы / ответимые вопросы` — доля ложных отказов; `неподтверждённые ответы / вопросы с недостаточными данными` — опасная доля. Единица — вопрос. Неполный отказ без указания существенной причины — частичная ошибка и отдельная диагностическая метка.
- **Пример:** 8 вопросов без данных: 6 корректных отказов, 1 расплывчатый отказ, 1 выдуманное число → 6/8=75%, опасные ответы 1/8=12,5%. Среди 10 ответимых 2 ошибочных отказа → 20%.
- **Нужно:** gold-статус и причина отсутствия; два разметчика проверяют по замороженному корпусу и as-of. «Нет в нашем корпусе» не означает «не существует нигде».

### 1.6 Конфликты и версии

- **Что:** `корректно выявленные и объяснённые конфликты / размеченные конфликтные вопросы`. Единица — вопрос; обнаружение без объяснения и без источников считается неполным. Отдельно ложные конфликты / вопросы без конфликта.
- **Пример:** из 4 конфликтов 3 обнаружены и объяснены → 75%; из 6 случаев без конфликта один ошибочно назван конфликтом → 16,7%.
- **Нужно:** пары документов с версиями, датами и правилами совместимости; другой разметчик проверяет их смысл. Пересмотр версии не обязательно является ошибкой источника.

### 1.7 Скорость, вызовы и затраты

- **Что:** время от принятия вопроса до ответа, число фактически совершённых вызовов и стоимость одного запуска. Записывать каждый запуск, включая неуспешный. Для времени/вызовов показывать медиану, минимум, максимум и `n`, а не только среднее; итоговые расходы — сумма по всем вызовам.
- **Формула расходов:** сумма `(input_tokens × тариф_input + output_tokens × тариф_output)/1 000 000` плюс известные фиксированные/другие платежи; актуальная валюта и дата тарифа обязательны. Нет токенов или тарифа → «стоимость не измерена», не 0.
- **Пример:** времена 2, 4, 9 с → медиана 4 с, диапазон 2–9 с; 3 вызова на 3 вопроса → 1 вызов/вопрос. Эти величины синтетические.
- **Нужно:** timestamp начала/конца, request_id, статусы, счётчики токенов и выставляемые тарифы. Алексей проверяет, что повторы и неудачи не потерялись. На малом n p95 нестабилен, поэтому диапазон информативнее.

### 1.8 Симулятор: правильность, а не прибыль

- **Что:** `прошедшие заранее заданные проверки / все применимые проверки`; единица — отдельный независимый тест-инвариант. Критические нарушения показывать отдельно по числу и характеру, не компенсируя 1 опасную ошибку 99 обычными успехами.
- **Пример:** 9 из 10 проверок → 90%, но 1 случай исполнения до публикации — критический провал; сценарий не готов к демонстрации как корректный.
- **Нужно:** фиксированные входы, ожидаемые события, расчёты руками и журнал выходов; Константин готовит, Владимир или Тимофей перепроверяет. Набор тестов не доказывает отсутствие ошибок вне выбранных случаев.

## 2. Показатели финансовой отчётности

Применять к одному и тому же юрлицу или консолидированной группе, единому стандарту, одинаковой валюте и сопоставимым периодам. Сохранять исходные строки и точное название показателя. МСФО и РСБУ не объединять без обоснования; у финансовых организаций привычная выручка и операционная маржа могут быть неприменимы. Квартальные данные могут быть накопительными; остаток на дату не сравнивают с потоком за год. Пересмотренные сравнительные показатели — отдельная версия.

| Показатель | Смысл и формула | Входы и единицы | Требования и типичные ошибки |
|---|---|---|---|
| Выручка / доход | Исходная строка продаж/дохода, не расчёт. | Значение за период, рубли и масштаб, локатор. | Не приравнивать доход финансовой группы к выручке промышленной компании; не сравнивать 9 месяцев с годом. |
| Чистая прибыль | Прибыль после расходов и налога за период. | Значение в рублях; группа или доля акционеров отдельно. | Не путать прибыль группы с приходящейся на акционеров; убыток записать отрицательным. |
| Изменение показателя | `Δ=x_t−x_prev`; абсолютное изменение. | Одинаковые единицы и период. | При несопоставимых объёмах группы пояснить ограничения; иногда абсолютное изменение понятнее процента. |
| Рост выручки или прибыли | `(x_t/x_prev−1)×100%` при положительном, ненулевом предыдущем значении и сопоставимости. | Оба исходных значения и периоды. | При нуле — отказ от деления; при отрицательной базе — не называть знак формулы обычным «ростом», показать значения и изменение, попросить методику. |
| Операционная маржа | `операционная прибыль/выручка×100%`. | Две строки за один период, одинаковая валюта. | Только при сопоставимом определении и ненулевой выручке; разницу марж выражать в процентных пунктах. Для некоторых финансовых организаций неприменима. |
| Поток от операций | Денежный поток от операционной деятельности за период. | Строка отчёта о движении денег, рубли/масштаб. | Это поток, не остаток; скобки — возможный отрицательный знак. |
| Учебный FCF | `операционный денежный поток − денежные капзатраты` (положительная величина оттока). | CFO и конкретные статьи приобретений, одинаковые единицы и период. | CapEx в документе может быть отрицательным; определение не универсально, не приписывать его эмитенту. Оставить расширением, если состав нельзя подтвердить. |

Для первого завершённого пути достаточно чистой прибыли или выручки и сравнения двух сопоставимых периодов; маржу, CFO и FCF добавлять по мере доступности подтверждённых строк. Это ограничение функциональности, не выбор компаний-заказчиков.

## 3. Условная симуляция: показатели и инварианты

- Капитал на момент t: `V_t = cash_t + quantity_t × price_t` при корректной цене, валюте и корпоративных событиях. Отсутствие цены не заполнять будущим значением без заранее оговорённой политики; для первой версии лучше остановить расчёт.
- Доходность с учётом расходов: `(V_end/V_start−1)×100%` при `V_start>0`, без внешних вводов и выводов капитала. Комиссии и проскальзывание уже учтены в `cash` и цене исполнения; не вычитать их повторно. Денежные потоки и дивиденды учитывать по отдельной утверждённой политике.
- Пиковый капитал `peak_t=max(V_0,…,V_t)`; просадка `DD_t=(V_t/peak_t−1)×100%`; максимальная просадка — минимум DD_t, часто сообщается положительной величиной `−min(DD_t)`. Использовать один интервал оценок и `peak_t>0`.
- Комиссии `Σ fee_trade` в валюте счёта. Проскальзывание для покупки отражать повышением, продажи — понижением цены от заданной опорной цены; отдельно показать денежную оценку и допущение, не повторно вычитать.
- Сравнение: денежная позиция и buy-and-hold с одинаковой датой начала, окном, ценовой серией и комиссией, одинаковым учётом корпоративных событий; задать общую стартовую долю или отдельно показать различающуюся экспозицию. Денежный вариант без процента — явное допущение. Показать разницу доходности в процентных пунктах, а не относительные проценты.
- Правило фиксируется до проверки. Хранить конец отчётного периода, доказанное время/дату публикации, версию факта, время сигнала, календарь и время/цену виртуального исполнения. Запретить любые факты, появившиеся после сигнала. Если только дата известна — следующая торговая сессия после этой даты; если дата неизвестна — отказ. Учесть выходные, остановки и доступность цены. Если split/dividend не обработан и влияет на ряд — отказ или ограничение периода. Не оптимизировать порог по финальной выборке.

### Вымышленные учебные расчёты

**Показатели.** У компании «Пример», группа по МСФО: выручка 100 млн руб. в 2024 и 120 млн в 2025; операционная прибыль в 2025 — 18 млн. Рост `(120/100−1)×100 = 20%`; маржа `18/120×100 = 15%`. Если маржа в прошлом году 13%, разница `15−13 = 2 п.п.`, а не рост на 2%. 2024 и 2025 должны быть одинаковой длительности и единицы — иначе отказ. Числа выдуманы.

**Симуляция.** Начальный капитал 10 000 руб.; купить 20 штук по 100 руб., комиссия 1 руб. → денежный остаток 7 999. Позже продать по 105, комиссия 1 → капитал 7 999+2 100−1=10 098 руб.; доходность 0,98%, комиссии 2 руб., проскальзывание 0. Для траектории 10 000 → 9 500 → 10 098 пики 10 000, 10 000, 10 098, просадка 0%, −5%, 0%; максимальная просадка 5%. Цены и события искусственные; 9 500 — заданная промежуточная оценка всего капитала, не дополнительная сделка. Базовая денежная позиция 10 000 → 10 000 без процента, 0%; разница +0,98 п.п. Это не прибыль на реальном рынке.

## 4. Набор и эксперимент

Ориентир при наличии ресурсов: 60 вопросов, 20 dev и 40 закрытых; это не требование преподавателя. Состав закрытого примера: 8 прямых фактов, 8 формул, 5 сравнений/масштабов, 6 отсутствий, 5 конфликтов/пересмотров, 4 вопроса с временной логикой, 4 ошибочные предпосылки/инъекции — всего 40. Категория является основной, дополнительные теги допускаются; избегать двойного счёта общей точности. В dev ещё 20 примеров схожих типов. Документы должны позволять честно разметить такие случаи; если реальных пересмотров не найдено, использовать явно синтетические и не выдавать их за факты. Учитывать несколько обязательных фрагментов. Если подготовить 60 не получится, сообщить фактический n и отдельно категории с нулём.

Эталон: `id, question, company/group, standard, as_of, document_hash/version, source_page/table/row/column, correct_status, answer_value/unit/scale/period, accepted_alternatives, formula, tolerance, conflict_or_missing_reason, author, independent_reviewer, adjudication`. Один готовит; другой независимо сверяет, разногласия разрешает Тимофей с письменным основанием. Подготовка правил и dev — до закрытой оценки, заморозить хеши. По возможности отдельный holdout-документ/эмитент оценивает перенос; иначе прямо указать ограничение.

Сравнение: A — один поиск + ответ модели; B — фиксированный процесс с поиском, валидацией и калькулятором; C — один агент с теми же инструментами. Те же документы, модель, вопросы, условия источников, допустимые результаты и зафиксированные бюджеты. B/C ближе к сравнению управления; A/C одновременно меняет инструменты и управление. Записать фактические шаги и цену; равный потолок не означает равную стоимость. По каждому вопросу показывать парные исходы A/B/C и классификацию ошибок.

Предлагаемые ориентиры для предварительной приёмки: 80% строгой точности, 90% подтверждённости, 80% корректных отказов и 0 известных критических ошибок времени на заданных тестах. Они заимствованы из старого проекта как ориентиры, но **не подтверждены измерениями или статистическим обоснованием**; команда должна согласовать их до заморозки и не подменять требование курса. На 5 отрицательных примерах одна ошибка изменит показатель на 20 п.п.; поэтому указывать `x/n`, диапазоны неопределённости при возможности, отдельные категории и не заявлять точность на всём российском рынке. Количество времени ручной проверки измерять на одинаковых задачах и людях; учебный тест не доказывает бизнес-экономию.
