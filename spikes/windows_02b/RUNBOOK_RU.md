# WIN-02B: сценарий приёмки в отдельной чистой Windows 11 x64

Этот пакет подготовлен без доступной VM. Он не является квитанцией успешной
приёмки. Не запускать installer повторно на исходном компьютере ради отметки
clean VM. Не отключать защиту Windows и не менять сеть/виртуализацию хоста.

Внутри — тот же WIN-02 v4 installer, собственный сборщик сведений и шаблон
происхождения среды. Новые Python/модели/SDK в guest не устанавливаются.
Сборщик использует системный .NET Framework4.8+, не требует pip/PowerShell policy
changes, не устанавливает и не удаляет приложение, не меняет сеть/настройки.
Он не посылает сетевые запросы и не обращается к модели.

## 1. Получить настоящий тестовый ресурс

Нужны доступная чистая Windows11x64 guest или отдельно переустановленная чистая
машина, разрешённый образ ОС, обычная учётная запись без членства в Administrators
и способ управления/передачи файлов. Зафиксировать источник образа и как получено
чистое состояние (fresh install либо возврат к известному чистому snapshot).
HypervisorPresent=true, новый venv или новая папка этого не доказывают.

Перенести ZIP в выбранную среду разрешённым способом. Это локальный частный kit;
`host-guard.private.json` содержит только salted comparison hash исходного
компьютера, не raw machine identifier. Не размещать kit/этот файл/сырые guest logs
в публичном Git. У сборщика собственная подпись/production trust не заявлены;
любая блокировка Windows фиксируется, защита не обходится.

Проверить размер installer22434104байт и SHA256:

```text
f69523d44f474eacb0905d66e4f90294a3124a3d348c44222e6fe8e9ec3e56cf
```

Уже существующий ZIP receipt содержит hash всего kit. После изменения provenance
или файлов guest hash ZIP изменится — не приписывать ему исходный hash.

## 2. Сохранить происхождение и исходные настройки guest

В `provenance.json` заполнить `os_source`, `clean_state_note`, выбрать `kind`
из fresh_install/reverted_clean_snapshot/separate_clean_machine, дать уникальный
`session_id` (латиница/цифры/`_`/`-`,1–64 символа). `clean_state_declared=true`
ставится только после фактической проверки исходного состояния. Это декларация
оператора, не независимое доказательство и не проверка финансовых фактов человеком.

Сохранить исходные масштаб/контраст/сеть **гостевой** системы, источник времени
и снимки первого состояния. Отключить сеть гостя разрешённым способом. Не менять
сеть хоста. WindowsApps execution aliases Python сами по себе не доказывают
установку интерпретатора; отдельно проверить installed apps/источник чистого образа.
Существующий Qwen на хосте не запускать, не опрашивать и не перенастраивать.

Из папки kit выполнить одну команду (Codex — через разрешённый CLI, не через
автоматизацию терминала интерфейсом Windows):

```text
GuestEvidence.exe preflight
```

На исходном компьютере ожидается отказ `original_host_rejected`, exit21.
Отказ проверен реально при подготовке kit, это не guest test. Сборщик не собирает
guest environment до этой проверки и не запускает installer. Сравнение является
защитой от случайной подмены среды, не аутентификацией VM; правка config не создаёт
доказательства чистоты. Не использовать изменение host-guard для обхода отказа.

В guest сборщик сохраняет частный JSON в
`LocalAppData/ProjectPractice/WIN02B-evidence/<session_id>/preflight.json`.
Он фиксирует OS/build/Framework/current-token и administrator-group признаки,
известный global Python по PATH и32/64-bit registry, Ollama по PATH, состояния
сетевых интерфейсов без IP/MAC, собственное состояние установки. Ничего из найденного
не запускается. Отсутствие известных записей и inactive NIC недостаточно для
полной приёмки: происхождение среды/действия проверяются отдельно. Сборщик всегда
оставляет `guest_accepted=false`. При blocker остановить зависимую часть и
зафиксировать причину, не ослаблять guards. Повторный checkpoint в том же session
не перезаписывается — для нового прогона нужен новый session_id.

## 3. Пройти именно интерактивный путь

1. Запустить `ProjectPractice-WIN02-setup.exe` обычным пользователем, пройти
   мастер установки без `/S`, зафиксировать отсутствие повышения прав.
2. Открыть созданный Start-menu ярлык. Снять первый экран **до кликов**: белый
   кадр, пустое окно или ошибка не считаются исправным запуском. Установка должна
   находиться вне Git/OneDrive, путь содержит кириллицу и пробелы.
3. Открыть через native диалог встроенный own PDF:
   `LocalAppData/Programs/Проектная практика WIN02/app/assets/demo/own-demo-v1.pdf`.
   Не переносить сторонние issuer PDF в этот опыт. Проверить страницу1 и точную
   рамку вокруг Operating profit18, период2025, МСФО/группа/млнRUB. Рассчитать
   маржу — ожидание15,00%, текстовый результат и источник доступны.
4. Проверить фоновую задачу/реальный прогресс/отмену до завершения с пустым
   ответом; crash/no financial success; следующий расчёт должен восстановиться.
5. После UI-наблюдения разрешённым CLI выполнить установленный
   `ProjectPractice.exe --diagnose` из посторонней рабочей папки. Это фиксированная
   диагностика своего примера, не свободная команда worker. Сверить private Python/
   внутренние sys.path/isolated/no_user_site/source SHA/15,00%; сырой runtime.json
   остаётся в guest-local `ProjectPractice/WIN02/runs`.
6. Из kit выполнить `GuestEvidence.exe installed`. Manifest проверяется против
   hash исходного v4 payload; собрать readonly/shortcut/HKCU признаки. Это снимок
   состояния и не доказательство визуальной или голосовой доступности.

Данные own demo: PDF2327байт/420×360/SHA
`c749435d1d445664dd5b28f54e6fd19f5fbcdb91d505e6ac112d1ba7f4715451`.
Вымышленная группа/полный2025/МСФО/млнRUB: revenue120, operating profit18,
оба положительные. Publication unknown, human_reviewer=null. Не добавлять
эмитентов/OCR/формулы/модели и не исправлять expected по увиденному output.

## 4. Доступность и измерения

Проверить клавиатуру/фокус/текст UIA, реально слышимое чтение Narrator, системные
125–200% DPI, большой русский текст и настоящий OS high contrast. Менять и потом
восстанавливать только сохранённые настройки guest. Zoom PDF200 и render DPI2 не
заменяют OS200. Отправка команды Narrator/UIA Value не означает услышанное чтение.
Если звук/управление/настройка недоступны, оставить exact remaining gate.

Замерить setup/startup/idle/peak/cancel/close на конкретной guest. Не выдавать
первый процесс за OS cold boot; указать polling/кэш/число запусков/shared RSS.
Таблица10000строк — техническая нагрузка. Малый own demo не доказывает минимум
RAM всей программы или качество анализа новых финансовых документов.

Перед настоящими UI-действиями Codex читает computer-use skill; после наблюдённого
исхода завершает CUA completion_summary. Снимки/полный UIA/сырой звук/VM exports —
только приватный tmp, никакой автоматической загрузки в Git.

## 5. Закрытие и удаление с сохранением данных

Закрыть приложение, проверить отсутствие own worker. Создать собственный малый
контрольный файл в `LocalAppData/ProjectPractice/WIN02` с явным происхождением.
Выполнить `GuestEvidence.exe before-uninstall` — он сохраняет hashes только
собственных данных приложения, не сканирует профиль целиком.

Пройти обычный мастер удаления. Не выбирать удаление пользовательских данных;
стенд сохраняет их по умолчанию. Выполнить `GuestEvidence.exe uninstalled` и
сверить отсутствие собственных program files/ярлыка/HKCU entry/процессов,
совпадение hashes с before-uninstall. Null baseline, неполное чтение процессов
или неизвестный файл не превращать в pass. Не удалять оставшиеся данные/файлы
рекурсивно; только отдельное явное решение по известному собственному контролю.

## 6. Что считать итогом

Для реальной приёмки нужны: происхождение guest + фактические OS/account/runtime,
совпавший installer SHA, доказательства интерактивного install/shortcut/первого
экрана/собственного расчёта/отмены/сбоя/offline/close/uninstall/data preservation,
отдельные accessibility наблюдения и честные remaining gates. JSON сборщика
**никогда сам не помечает этап принятым**. Проверенные существующие source/path
guards и замороженные datasets не менять.

Не объявлять полный runtime parity: в WIN-02 остаются25 cross-root path errors;
69 original-root tests и10 package checks — прежние host evidence, не guest run.
Official private CPython3.12.10 — лабораторный кандидат, не утверждённый maintained
runtime публичного продукта. Собственная code-license/подпись/покупка сертификата/
production update и полный Windows matrix не оформляются этим kit. WIN-03/04/54
не становятся выполненными. Никаких реальных сделок/обещаний доходности.

Если ресурса нет, оставить статус `resource_blocked_kit_prepared`, сохранить
квитанцию подготовки и остановиться. Возвращаться к исполнению этого сценария
после появления конкретной чистой среды, без повторного изготовления такого же kit.
