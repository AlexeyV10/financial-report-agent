## Где находится и как проверить

- data/question_sets/kp2_v1/questions.json — полные вопросы, контекст/версии/периоды/единицы, эталоны, локаторы, split/история/способ воспроизведения.

- data/question_sets/kp2_v1/manifest.json — хеши файлов и входов, резерв, время фиксации, снимок исходников прототипа.
- assets/ в той же папке — отдельные собственные искусственные missing/conflict и новый вариант расходов. Настоящий reference_bundle.json и default сценария шага 10 не менялись.


B/C принимают фиксированный UserQuery для годового роста, а не произвольный русский вопрос. lossless projection на этот шаблон возможен только для явно помеченных задач. Прямой факт может иметь корректный эталон, но наличие числа внутри ответа о росте не доказывает, что система ответила на исходный прямой вопрос. Для QA08 нельзя терять предпосылку. ## Структура, уровни исходов и контроль утверждений

Вопрос содержит стабильный ID, suite/category/tags/task, asset/origin/family, полный context (организация/группа/стандарт/метрика/документ/версия/периоды/единицы/mode/as_of/source), locators, expected, reproduction/capability, split/history и verification. Manifest фиксирует все входы/доказательства и 37 исходников/примеров подготовки. Изменение этих снимков обнаруживается. Для новых версий кода в будущем нужен отдельный явный run manifest/сопоставление версий; не редактируйте исторический снимок, чтобы спрятать изменение.

Expected.layer различает financial/user/scenario. Expected.reason_namespace отделяет код financial_tool от отсутствия исходной версии в reference_inventory и от ошибки интерфейсного периода user_path. Состояние агента проверяется поверх семантического результата: call_limit/timeout/error не становятся корректным missing. QA07 сохраняет старый неуспех в history, а требуемый финансовый исход остаётся правильным отказом.

У ответов выходы типизированы: measure, decimal-string value, currency, scale, полные periods, precision/rounding/tolerance, evidence_ids. Процент — процент, не RUB; номинал в миллионах не равен тому же числу в миллиардах. Величины показываются по объявленному округлению; внутренний длинный growth_pct не сравнивается напрямую с двухзначным growth_pct_display. Absolute_tolerance=0 относится к заявленному округлённому представлению, а не обещает точность исходного отчёта выше опубликованных миллионов.

У отказов outputs пуст, formula=null; никакой скрытый ожидаемый процент/ложный ноль не задаётся. Locators эталона всё равно сохраняются как база проверки, но отказ не обязан цитировать недоступные числовые факты. Required_evidence_ids относятся к числовым выходам. Mandatory_warnings — минимальные смысловые ограничения ответа/контекста, не универсальная проверка наличия буквальных строк в любом API-конверте. UI01 не использует отчёт и не требует финансовых предупреждений; у synthetic-компонента caller обязан сохранять явный origin.

validate_claim_context — только договор для **будущего нормализованного структурированного утверждения**, не готовый grader свободного текста. Правильные15,30 без компании/группы/стандарта/полных периодов/единицы/версии/as_of/точных Evidence не проходят. Текстовый разбор, извлечение всех существенных утверждений/предупреждений и правила подсчёта в реальных ответах предстоит добавить на шаге12; автоматическая оценка качества здесь не заявляется.
