## Текущий технический пакет — шаг13

Актуальный пакет текущего кода: **delivery/kp2-local-step13-v1-2026-11-09.zip**, рядом одноимённый .receipt.json. Явный список — packaging/kp2_local_v1_files.json, внутренний PACKAGE_MANIFEST.json фиксирует каждый файл. Полная инструкция — [local_demo.md](local_demo.md). Для проверки/восстановления используйте scripts/package_project.py, для изолированных режимов — scripts/run_local.py. Пакет не содержит первичный PDF/страницы/полный текст/индекс/модель/бинарники/секреты. Он включает только выбранные технические материалы и доказательства, а не весь архив истории/КП1.

Из новой распакованной копии в отдельном no-pip venv MSYS2 CPython3.14.7 прошли267 unit-тестов; 8 минимальных и4 поисковых интеграционных случая, отдельно один normal настоящего C/LLM. PDF/индекс для личной поисковой проверки копировались только в исключённую tmp/ копии, модель использовалась прежняя на том же компьютере. Это не установка модели с нуля на другом ПК и не новый замер качества. Первый импортный сбой при -I, MSYS2 bin/Scripts layout и отсутствие пустой tmp/ сохранены/учтены в инструкции и восстановителе; прежнее ядро/тесты/gold неизменны. Итоговая проверка именно выдаваемого ZIP отражается в receipt/evaluation шага13. Прежние метрики и C top1 call_limit не переписывались.

## Восстановление

Сравнить хеш ZIP с сохранённым receipt, распаковать в новую папку и открыть в её корне PowerShell. Хеш подтверждает совпадение байтов, не личность автора. Проверен CPython 3.14.7 на Windows, без внешних Python-зависимостей.

```powershell
python scripts\build_review_archive.py --verify-only delivery\stage1-local-v2-2026-11-09.zip
```

При запуске из распакованной папки укажите фактический путь к ZIP; он не вложен сам в себя.

```powershell
python scripts\check_stage1.py
```

```powershell
python -m unittest discover -s tests -v
```

Ожидается 4/4 и 41 тест. Успешный прогон подтверждает поведение на ручном JSON; истинность исходных ячеек не проверяется без первичного документа. Источник и локаторы сохранены в docs/source_verification.md. Происхождение assistant_checked не подменяется человеческой приёмкой.

## Сборка

После реального изменения кода или данных сначала сохранить свежие результаты:

```powershell
python scripts\check_review.py
```

```powershell
python scripts\build_review_archive.py
```

Скрипт берёт только явный список, проверяет состав/CRC/хеши, запускает распакованную копию в новой локальной папке через python -I. Это тот же компьютер и интерпретатор; другие люди или ноутбуки не являются условием. Сеть и публикация при сборке не используются.

Зафиксированную версию нельзя молча подменить: если исходные байты изменились, выбрать новое имя/версию архива и согласованно обновить пути. Повторная сборка с изменившимся временем лога может иметь другой хеш; повторяемость поведения не означает побайтное совпадение при разных входах.

Публикация именно выбранной PDF-версии и право распространять копию остаются неизвестными. Локальный технический архив не создаёт лицензию и не разрешает историческое исполнение. Все существенные решения принимает пользователь, технические проверки выполняет Codex.
