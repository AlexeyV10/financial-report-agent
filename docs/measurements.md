**Отдельный диагностический повтор** `run-02-environment-retry/` объявлен до запуска в retry-context.json, получил собственные протокол/хеши. Повторён тот же порядок и один проход; это не замена первого результата и не подбор лучшего ответа. SC02 уже был открыт первым проходом, во втором не настраивался. Это один числовой вопрос и два отрицательных, все dev/open. Четыре claims — два исходных факта, разность, отображаемый процент; формула и её подстановка проверяются как обоснование/повтор, не дополнительные независимые факты. Число без группы/стандарта/полного периода/единиц/версии/mode/as_of/точных Evidence не проходит. Проверяется соответствие фактического payload тексту фиксированного renderer и обязательные предупреждения. Любая лишняя числовая строка вне его узкой грамматики отвергается. Это не универсальная семантическая оценка свободного текста или всех бизнес-утверждений. У отказов/сбоев без claims подтверждённость неприменима; нулевой знаменатель не даёт100%.

Разница вариантов: B детерминированно вызывает инструменты, C выбирает разрешённые действия настоящей моделью; финальный текст у обоих программный. Данные/калькулятор/renderer и структурированные входы одинаковы. Русские формулировки спроецированы на существующий шаблон только для QA03/06/07/UI01, общего NLP нет. QA01/02/04/05/08 не запускались через default growth и остаются requires_adapter. Превосходство агента, статистическая устойчивость, качество на российском рынке и бизнес-экономия не доказаны.

## Воспроизведение без новой модели

Из корня проекта:

```powershell
python scripts\measure_step12.py replay --run-dir evaluation\step12_2026-11-09\run-02-environment-retry
```

Получается то же results.json по сохранённым raw и gold. Команда не запускает модель, поиск, калькулятор или симулятор и не требует наличия PDF/индекса для пересчёта. Дополнительный guarded replay запрещал создание socket и импорт production-модулей ответа: совпадение подтверждено в offline-replay-proof.json. Для run-01 также сохранён совпавший offline-replay.txt. Хеши сырья и grader проверяются; попытки незаметно поменять данные выявляются.

Новый эксперимент требует нового каталога: `prepare --run-dir evaluation/<новый-путь>`, затем отдельный `collect`, `grade`, `replay`. Prepare фиксирует весь план до получения ответов; collect отказывается повторно писать raw, grade не затирает старые results. При недоступном сервере C остаётся явным сбоем, mock/manual вместо него не включаются. В ограниченной среде для текущего Ollama может потребоваться разрешённый запуск helper вне песочницы; не меняйте pin и не скачивайте веса как «исправление» Access is denied.

**Проверки кода: 255 unit-тестов (231 прежний +24 оценщика) и8 CLI-проверок, включая2 offline replay, прошли.** Первый дефект оценщика до заморозки исправлен и описан в development-grader.json; модель тогда не вызывалась. Все37 прежних исходников/данных и frozen-набор сохранены. Инструкция шага11 и его history отражают момент подготовки; результаты последующих запусков хранятся отдельно, поля frozen history не переписаны. Оригинальные исследования/КП1/архивv2 не менялись.
