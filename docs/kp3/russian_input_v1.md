# КП3-08: ограниченный русский ввод и уточненияv1

Разбор текста, выбор каталожных ссылок и финансовый ответ — три разных результата. На08 добавлены только новые модули `input_contracts.py`, `russian_input.py`, `input_binding.py` и отдельный CLI `parse_financial_input.py`. Они не меняют Catalog/Task/Outcome0.2, Request/Calculation/Outcome0.3, формулы07, поиск06, модель, сервис или UI. Библиотеки/LLM не добавлены, вызовов модели0.

## Объявленная грамматика

Это ограниченный разбор ключевых слов, а не понимание произвольного русского текста. За один запрос выбирается одна организация и одна зарегистрированная операция, до двух полных периодов и двух exact-документов. Для сложного порядка слов/смешанных окон есть структурированная форма; непонятное намерение не становится ростом по умолчанию.

| Формулировка | Нормализованное действие |
|---|---|
| «какая/какова/покажи/найди/сколько составляет выручка» | direct_fact_v1 |
| «абсолютное изменение», «разница», «на сколько рублей» | absolute_change_v1 |
| «на сколько процентов», «относительное изменение», «темп роста» | relative_change_v1 |
| «покажи ... в млрд рублей» | scale_v1 |
| «операционная маржа» | operating_margin_v1, OP/revenue |
| «правда ли ... снизилась/выросла/не изменилась» | сохранённая проверяемая предпосылка + absolute_change_v1 |
| «почему ... снизилась» | та же проверка направления, отдельное явное ограничение: причинное объяснение не поддержано |

Поддержаны формы выручк*, операционн* прибыл*, CFO/«чистый денежный поток от операционной деятельности»/«операционный денежный поток». Эти aliases не переопределяют проверенный смысл трёх definitions04. EBITDA/чистая прибыль/процентные и комиссионные доходы/денежные поступления/dividends/FCF/capex не подставляются. Банк/страховая группа/другой стандарт не переводятся в текущий нефинансовый IFRS-словарь.

Организации ищутся по runtime-каталогу, без default IDs. Объявлены несколько контролируемых форм: Сегежи/Сегежу/Сегежей→Сегежа, Фосагры→ФосАгро; Segezha — вариант существующего alias Segezha Group. Сопоставление без учёта регистра, ё/е и лишних пробелов. Это не универсальная морфология названий. Неизвестное явное имя и отсутствующее имя различаются; для произвольного нераспознанного названия предлагается выбор из каталога. Несколько совпадений не разрешаются первым элементом.

Полные годы требуют слова «год/годы»; общая подпись «2023 и2024 годы» задаёт окна01.01–31.12 в данном порядке. Первый/1/I–четвёртый/4/IV квартал,3/6/9месяцев и первое полугодие задают разные duration_type. «2024» без полного окна разрешается из каталога только если для каждого указанного года существует единственный тип полного окна; в настоящем каталоге2024 неоднозначен. «За квартал» без номера/года требует уточнения. Смешанные подписи нескольких разных окон в одной фразе отклоняются: общий первый маркер нельзя применить к обоим годам. Полные typed периоды в форме дают явный конфликт при несопоставимости. Квартал из разности YTD не создаётся; неподготовленный Q2 не допускается из automatic.

«Из [годового] отчёта за2024год» — ограниченный селектор исходного документа, его год маскируется при разборе запрошенного финансового периода. Он ищется среди полных годовых отчётов выбранной организации. Отсутствующий2026 не заменяется2025. Несколько таких source-оговорок не объединяются молча. Exact document/version выбираются также через структурированную форму; в тексте допустимо «документ phosagro-2024», проверяемое по каталогу. Неизвестный ID не игнорируется. Политики: «исходные отчёты/первоначальная версия» и «явные версии/сравнительная колонка». Их явное противоречие отклоняется.

Суммы: в рублях/тыс./тысячах/млн/миллионах/млрд/миллиардах рублей; в одном запросе — одно представление. Несколько масштабов требуют выбора. «В млрд» без валюты не дополняется рублём из default. Исходные единицы выводятся только из однозначно выбранных Fact, с видимым происхождением catalog_unique. Процент и amount не смешиваются; п.п. не зарегистрированы на07. FX не реализован.

Snapshot задаётся словом «снимок/snapshot» или полем формы; historical — «на дату/по состоянию на/что было известно» либо полем. В тексте момент: YYYY-MM-DDTHH:MM:SS±HH:MM либо Z. Голая дата/время без зоны требуют уточнения; она сохраняется как hint, а не конец отчётного периода. Противоречивые snapshot/historical не угадываются. Все8 real PublicationEvidence unknown: корректно разобранный historical запрос всё равно блокируется калькулятором07.

«На сколько изменилась» требует выбора абсолютного/относительного. «На сколько и на сколько процентов» сохраняет факт двух запросов и предлагает выбрать один для данного вызова; второе действие не объявляется выполненным. Для причинного «почему» направление проверяется отдельно, причина не выдумывается. Отрицания «не снизилась/не выросла» и противоречивые направления вне ограниченной грамматики дают явный unsupported. Текст с командами игнорировать проверки/выполнить код/подставить999 отклоняется; формулы/URLs/shell не исполняются.

## Контракты ввода

NormalizedInput `kp3-input-0.1`: `input_id, original_question, input_kind, raw_fields, fields, field_origins, assumptions, assumption_origin, hints, issues, unsupported_reasons, unfulfilled_requests, history, catalog_digest, language_version` плюс schema_version. Original_question хранится **точно**, без нормализации регистра/пробелов. Для формы сохраняются исходные частичные raw_fields. Происхождение каждого поля: unset/text/form/clarification/catalog_unique/operation. Assumption хранит kind=direction, asserted_direction, исходный text_fragment, requires_check=true и why_requested; origin=text/form/none. Предпосылка не является подтверждённым фактом.

Поля partial fields: `organization, consolidation, accounting_standard, operation_id, metric_ids, definition_ids, periods, documents, version_policy, source_unit, result_unit, mode, as_of, comparability_id`. Неизвестные поля запрещены. Нет value/formula/expected/gold/пути PDF/исполняемого URL. Organization может быть ID или именем/alias; metrics/definitions — списки из1–2 IDs, для margin OP/revenue в этом порядке. Documents — document_id/version_id, periods/source_unit используют строгую проверку0.2, result_unit — проверку0.3.

Form `kp3-form-0.1` имеет точные поля: schema_version/input_id/original_question/fields/assumptions. fields могут быть неполными. Форма здесь — JSON-схема/адаптер, Streamlit UI не создавался. Понятная явная часть original_question не может противоречить выбранным полям формы. Распознанная предпосылка не теряется при пустом assumptions; явный список не может развернуть её направление/скрыть «почему». Непонятная общая подпись формы не используется для угадывания её полей.

Синтаксический статус: parsed/awaiting_clarification/unsupported; некорректная схема/JSON — technical error. Это не финансовый answered. Binding `kp3-binding-0.1` отдельно имеет resolved/awaiting_clarification/unsupported/missing/conflict/error, normalized_input, clarifications, request0.3 либо null, assumptions. financial_status всегда null, calculations_performed=false. Missing/no_compatible_fact означает отсутствие совместимого подготовленного входа, не доказанное отсутствие строки в PDF. Source unit mismatch — conflict, неизвестный/дублирующийся ID/версия/изменение каталога — error.

## Выбор и уточнения

Сначала валидируются Catalog0.2 и его digest, версия языка, словарь и partial fields. Однозначные group/standard для явно выбранной организации, definition и исходная единица выбранных фактов показываются как catalog_unique; это вывод из текущего каталога, а не константы ФосАгро/IFRS/млн. При нескольких стандартах/определениях/версиях нужен явный выбор. Mode/операция/полные периоды не получают defaults. Percent выводится из зарегистрированной операции, не денежного поля0.2.

Выбор Fact требует полного сочетания организации, metric/definition, периода, exact-документа, политики версии и единиц. Candidate/structure_checked/нет Evidence/непроверенный документ не связываются как ready. Значения не используются для поиска/опций уточнения. Binder не подтверждает финансовый смысл заново и не проверяет байты PDF: соответствующие gates остаются в07. Для margin выбираются OP/revenue одного окна; окончательные проверки версии/единиц/сопоставимости/публикации выполняет07.

Уточнение — частичный typed patch к предыдущему **доверенному** normalized state. Оно заполняет unset, не меняя original_question/assumptions/ранее явный выбор. Разрешены явное исправление неразрешённого имени и дополнение неполного сравнения с сохранением уже указанного периода; заменённое неразрешённое значение сохраняется в history. Противоречивый patch/лишние поля/больше16 раундов — техническая ошибка, не финансовый отказ. Unknown/form raw values и history сохраняются. CLI повторно воспроизводит исходный input и список answers, а не принимает произвольный «готовый normalized JSON» как доверенный результат модели.

Это механизм целостности конфигурации/сессии, не подпись автора. Catalog digest не аттестует финансовую истину. Контекст/доказательства/состояние приложения поступают из доверенного setup; пользовательский текст/ответ на уточнение не создаёт admission/source checks/Fact/публикацию/доказательство сопоставимости. После смены каталога старая задача не разрешается повторно по старым ссылкам без нового ввода. При изменении грамматики требуется новая версия/manifest.

## Связь с калькулятором07

Resolved содержит Request0.3 с проверенными IDs и исходным вопросом, отдельно — assumptions/unfulfilled_requests. `probe_adapter` — явная узкая проверка передачи: заново разрешает normalized task, сравнивает **весь** binding, вызывает существующий07 и его validate_calculation_binding. Это не router/service/B09. Значения/формулы/готовый ответ парсером не передаются. Допустима проверка через уже существующий retrieval guard06; automatic/partial/изменённый source/index/export/config не обходятся.

Assumption check читает знак уже рассчитанного exact difference из trace07 (для absolute/relative), не пересчитывает формулу и не использует округлённый процент. Исходы supported/contradicted/not_checked; сохраняются утверждённое/наблюдаемое направления. При финансовом отказе или технической ошибке предпосылка остаётся not_checked. Причинное explanation_status=not_supported, объяснение причины не появляется. Отрицательная/нулевая база и остальные07 gates сохраняются.

## Запуск и доказательства

Input CLI — отдельный JSON `{kind:"text",input_id,question}` либо `{kind:"form",form:{...}}`. Файлы примеров: data/dev_cases/kp3_input_v1/cases.json. Запуск без расчёта:

~~~powershell
python -I scripts/parse_financial_input.py --catalog data/catalogs/kp3_corpus_v1/runtime_catalog.json --dictionary data/dictionaries/kp3_finance_v1/definitions.json --input tmp/input.json
~~~

`--answers tmp/answers.json` — последовательность partial field patches. `--probe` явно добавляет узкую интеграционную проверку07; нужны `--admission`, а для real ещё `--bindings --source-checks --resources` как в07. Опциональные `--index --config --lexicon [--exports]` — доверенные пути guard06. Никакой сетевой загрузки/модели/сервера/UI. Exit0 — binding resolved (с probe также корректный completed финансовый исход),3 — уточнение,4 — unsupported/missing/conflict binding,2 — technical error. Успех parse без probe не финансовый ответ.

Публичная проверка: `python -I scripts/check_kp3_input.py`;76 собственных открытых примера с отдельно вручную заданными ожидаемыми полями/намерениями/уточнениями. Builder не импортирует production parser/calculator. Ожидаемые semantics только в evaluation/fixtures; runtime их не читает. Новые unit-проверки включают формы/цепочки уточнений/подмену контекста/ложную предпосылку в обе стороны/технические ошибки. Финансовые эталоны узкой интеграции получаются прежним независимым reference07 над уже проверенными48 Fact, не из production-answer.

Результаты/первые ошибки/команды/сохранность — evaluation/kp3_08_2026-11-10/. Все примеры/источники известны разработчику, reserved unseen real=0, final freeze14 не выполнялся. Новых реальных Fact/публикаций/human_reviewed/прав нет. Старые QA07 C/call_limit,3/10financial и reserved financial n=0 не меняются от успешной unit/adapter проверки.
