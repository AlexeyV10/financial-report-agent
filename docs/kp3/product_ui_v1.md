# Продуктовая оболочка, история и экспорт КП3-13

Новая изолированная оболочка `app_kp3/product_app.py` объединяет готовые сервисы09–12. Старые интерфейсы09/12, их manifests, финансовые ядра07, parser08, C10 и A11 не изменены. Формулы в интерфейсе отсутствуют. P0 ограничен уже подготовленными источниками и словарём04; новые источники/OCR/операции/цены не добавлены.

## Запуск и экраны

Основное ядро проверяется MSYS2 Python3.14.7/SQLite3.53.4. Интерфейс использует прежний отдельный root/tmp/kp3-ui-cpython312: Python3.12.14, Streamlit1.67.0, Pandas3.1.1 и уже установленный Altair. Глобальные пакеты и старые venv не меняются. Из worktree13:

```powershell
$env:KP3_PRODUCT_CONTEXT = (Resolve-Path tmp/service-context.json).Path
& '../../tmp/kp3-ui-cpython312/Scripts/python.exe' -m streamlit run app_kp3/product_app.py --server.address=127.0.0.1 --server.port=8513 --server.headless=true --server.fileWatcherType=none --browser.gatherUsageStats=false
```

Для открытия страниц нужен имеющийся pdftoppm в PATH только процесса. Ресурсы задаются доверенной картой tmp/local-resources.json. Для новой копии сначала нужны зарегистрированные PDF и новый индекс06; успешное чтение каталога само по себе этого не доказывает. Точные рабочие команды/окружение сохранены в evaluation13. Вес модели/первичные страницы/экспорты остаются в ignoredtmp.

Обзор объясняет scope и отдельно проверяет файлы/индекс или локальную модель без генерации. Анализ даёт русский вопрос08 или форму пяти операций. Компания/действие/периоды/версии/политика/mode выбираются явно. Для маржи используются profit/revenue; для изменения сохраняется previous/current; рублёвый scale не является FX. Стандарт/границы/definition не заполняются скрытым default: binder08 либо выводит их при однозначности с происхождением поля, либо уточняет. Форма не редактирует Fact values. Русский parser ограничен объявленной грамматикой08; не каждая естественная формулировка поддерживается. Несовместимый период не превращается в growth.

Метод выбирается явно: B — обязательный поиск06 и gates07 без модели; C — готовый настоящий tool loop10; A — единственный выбор11. Нет B fallback или replay под другой буквой. Сначала действуют parser/clarification/source gates существующих контроллеров. Недоступная модель — технический исход; запуск прежнего root/scripts/local_model.ps1 start и выбор B являются отдельными действиями пользователя. Модель pinned Qwen3:4b/Ollama0.40.15, fixed localhost11435/cloud disabled; новая модель не загружается.

Answer показывает исходный вопрос, число/единицы/полные периоды, входы, формулу, округление, предпосылку и невыполненное why. JSON/usage/trace/metadata находятся в раскрываемой диагностике. Evidence содержит точную версию, страницу, строку/колонку, аудит/provenance/publication. SourceViewer09 сверяет bytes/SHA до и после рендера через Poppler; только зарегистрированные источники и страницы. Ссылка не новая сверка финансового смысла. Смена ввода/метода/контекста/страницы отзывает предыдущие права просмотра и скрывает активный ответ.

Сценарий12 вызывается через тот же сервис, с заметной маркировкой own synthetic до/после расчёта и в экспорте. График — отображение готового ledger, не новая арифметика; ось капитала не принудительно начинается с нуля. Расходы, целые лоты, деньги/удержание и maxDD остаются из12. Реальный financial Answer можно явно выбрать из истории для новой проверки bridge12; старый архив не объявляется свежим финансовым ответом. Все8 real publication unknown; реальные торги остаются blocked.

## История0.1 и повторы

`product_history.RunStore` принимает только доверенный путь под ignoredtmp; UI по умолчанию tmp/product13/history. Переменная KP3_PRODUCT_HISTORY — только настройка запуска (в AppTest отдельная временная папка), не поле вопроса. Record schema `kp3-history-0.1`: record_id, saved_at UTC, context_digest, payload, payload_sha256. Payload имеет ровно kind/source/answers/result, kind financial/scenario, а результат — один из валидируемых Answer B0.1/C0.2/A0.1 или scenario0.1. Неизвестные/лишние поля wrapper, duplicate JSON keys, некорректный UTF-8/NaN, размер>8MB, unsafe ID и повреждение checksum отклоняются. Checksum обнаруживает повреждение, не является цифровой подписью против владельца локальной папки.

Ключ = canonical digest намерения, уточнений, метода, live context и explicit nonce. Live fingerprint включает фактические PDF/index/manifest/exports; catalog/config/admission/dictionary проверяются контекстом. Повтор кнопки/refresh нового UI-сеанса с тем же input использует nonce0 и тот же saved record, без контроллера/модели. Разные каталоги, периоды, единицы, версии, as_of и методы не делят Answer. Run ID включает namespace папки истории: два отдельных store не конфликтуют в сервисной папке запусков.

Сначала exclusive `.claim`, затем вызов одного готового контроллера и валидация его результата. Запись: временный файл в той же папке, flush/fsync, атомарный exclusive hard link к конечному ID, удаление только собственного temp. Существующий record не перезаписывается. При crash остаётся claim: автоматический повтор запрещён, нужна явная новая попытка. «Новый запуск» выбирает новый nonce/run_id, прежняя ошибка сохраняется. Открытие истории только читает сохранённый снимок, не вызывает модель/повторный финансовый расчёт и явно сообщает об отсутствии свежей проверки источников. Целостность источника при отдельном открытии страницы проверяется живым SourceViewer.

Собственный экспорт — canonical JSON wrapper и Markdown с вопросом/статусами/исходными значениями/локаторами/периодами/версиями/публикацией/ограничениями/предпосылкой/usage/trace. Unknown не становится нулём; source_usage сценария сохраняет исходные расходы A/C, новых вызовов у сценария0. Markdown экранирует пользовательский HTML/ссылки/backticks; JSON внутри блока содержит безопасные Unicode escapes. Никакой eval/exec/произвольный shell/URL не вызывается.

После сбоя браузерного ожидания стандартной Streamlit download-кнопки введён отдельный `HistoryDownloads`: явно выбранный собственный record, localhost attachment JSON/Markdown, фиксированный маршрут/safe ID/allowlist extensions/no-store/no-sniff. Файл формируется из проверенного record, не произвольного пути. Предыдущий record отзывается при смене ввода/раздела. Это не экспорт первичных PDF/страниц/полного текста/индексов/модельных весов. История локальная и не резервная копия; ошибки/прерванные claims не запускаются молча заново.

## Подготовка и границы доказательств

Раздел источников разделяет file/extraction/preparation/provenance. Готовность существующего каталога не качество автоматического extractor: prepared48checked и automatic40/48/6из8 остаются разными.
