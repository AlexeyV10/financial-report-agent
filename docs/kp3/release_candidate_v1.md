# Кандидат выпуска kp3-rc1

Это проверяемый локальный кандидат ограниченной учебной версии. Он соединяет неизменное финансовое ядро, оценённое на14/16, выбранный после16 интерфейс «Рабочий стол» и отдельную проверку целостности/готовности17. Завершение всего первоначального P0, отчёта18, полного пакета19 и отправки20 не заявляется.

## Поддерживаемая граница

| Возможность | В кандидате |
|---|---|
| Каталог | 2 нефинансовые группы МСФО, 8 exact-PDF-версий, 48 проверенных ассистентом Fact/Evidence |
| Ввод | Ограниченная русская грамматика08 либо явная форма; конкретные уточнения, исходный вопрос и предпосылки сохраняются |
| Расчёты | Прямой факт, абсолютное/относительное изменение, масштаб суммы, операционная маржа; общий калькулятор07 |
| Методы | B по умолчанию без модели; настоящие A/C доступны явно и требуют подготовленных pinned-модели и сервера |
| Доказательства | Полные периоды/единицы/версии/строка/колонка/страница, trusted local exact-page viewer; первичная страница не включена в экспорт |
| История | Собственные JSON/Markdown снимки, durable dedup, без генерации при открытии; смена контекста скрывает старый ответ |
| Сценарий | Собственные искусственные данные12; реальные сделки не исполняются |
| Время | Snapshot поддержан; все 8 real historical/real-source scenarios заблокированы при неизвестной публикации |
| Подготовка PDF | Существующий ограниченный CLI06 и восстановление уже зарегистрированного exact-файла13; общего интерфейса загрузки/проверки/допуска нового PDF нет |
| Оценка | Известный корпус14/16 и offline replay; unseen/holdout=0, без утверждения общего качества модели/рынка |

Полный аудит P01–P17 находится в `evaluation/kp3_17_2026-11-10/candidate-audit-before.json`, итог допуска и фактические результаты — в acceptance/report/final-audit этой папки. Ограничение загрузки PDF, ограниченный язык и отсутствие полного пакета остаются видимыми; никакая успешная регрессия не делает их выполненными обещаниями.

Выручка означает проверенную строку отчёта, OP — report-defined subtotal, CFO — конечный signed net итог операционного раздела. Состав OP двух групп различается. Segezha CFO original/comparative не исправлены и не объявлены эквивалентными. Relative требует положительную базу; маржа — одной exact-версии/группы/полного периода/единиц. Нет FX/FCF/capex/EBITDA/банковских доходов/новых формул или квартала из разности YTD. Денежные результаты точные, проценты HALF_UP2. Candidate/automatic без Evidence не допускаются.

## Проверка кода без частных ресурсов

Из корня checkout, после создания пустой исключённой tmp-папки:

```powershell
C:/msys64/ucrt64/bin/python.exe -X utf8 -I scripts/check_kp3_release.py --profile code --report tmp/rc-code-new.json
```

Успех означает только `code_verified_runtime_not_checked`. Он не обещает наличие PDF, модели или рабочего UI. Отчёт создаётся только в новом пути под tmp; существующий файл не перезаписывается. Manifest версии — `data/releases/kp3_rc1/manifest.json`; собственные файлы связаны SHA-256, источник/первичные страницы/веса туда не вложены.

## Готовность B и проверка сквозного пути

Основной интерпретатор проверен: Python3.14.7 MSYS2, SQLite3.53.4. Уже имеющийся UI venv — отдельный CPython3.12.14/Streamlit1.67.0/Pandas3.1.1. Глобальные пакеты и старые venv не меняются; установка зависимостей и запуск модели автоматически не выполняются.

На текущем компьютере новый checkout — `tmp/kp3-17-worktree`. Его собственные `tmp/service-context.json`, `local-resources.json`, `freeze-resources17.json`, `export-resources.json`, `retrieval-run-17/` содержат доверенные пути. PDF не копировались/не скачивались заново; восемь pinned exports повторно использованы, индексы построены в новом пути существующим06. Worker/OCR не запускались. Проверки не выводят полный текст или страницы в Git.

```powershell
C:/msys64/ucrt64/bin/python.exe -X utf8 -I scripts/check_kp3_release.py --profile B --context tmp/service-context.json --resources tmp/freeze-resources17.json --report tmp/rc-b-new.json
```

Профиль B требует только 8 PDF и prepared SQLite/sidecar (10 ресурсов), а не веса модели/automatic index/exports. В общей карте могут быть дополнительные известные pinned-ресурсы, но они не становятся зависимостью B. Сервис проверяет реальные source/index/config/catalog bindings; проверка готовности не выполняет поиск или финансовый расчёт. `runtime_ready=true` относится только к выбранному профилю и этим байтам.

Для отдельного известного smoke с историей/выгрузкой/trace/evaluator:

```powershell
C:/msys64/ucrt64/bin/python.exe -X utf8 -I scripts/check_kp3_release.py --profile B --context tmp/service-context.json --resources tmp/freeze-resources17.json --smoke --work-dir tmp/rc-smoke-new --report tmp/rc-smoke-new.json
```

Это evaluator-only проверка14 выбранных известных financial forms (7numeric/7refusal), одного уточнения, двух технических сбоев и двух прежних scenario cases. Runtime получает только source/answers, не case/gold/targets/expected; затем прежний evaluator14 сверяет Answer и независимый gold14. Проверяется равенство Answer/run_id/trace/входов собственному JSON, встроенному JSON Markdown и истории, повтор без нового запуска, представление числа тем же UI helper. Новых финансовых эталонов, исходных фактов и итогового benchmark нет. Все семейства известны разработчику.

## Запуск и остановка интерфейса

```powershell
& scripts/release_ui.ps1 diagnose
& scripts/release_ui.ps1 start
& scripts/release_ui.ps1 status
& scripts/release_ui.ps1 stop
```

Новый порт — localhost8522. Launcher проверяет manifest/B/UI dependencies, создаёт отдельную историю и квитанцию PID/путь/время/версия/manifest SHA. Совпадение HTTP health без собственной квитанции не доказывает нужную версию: занятый другим приложением порт вызывает отказ. Остановка касается только собственного процесса. Старые интерфейсы8509/8512/8513/8521 и сервер модели не останавливаются. Ошибка запуска не даёт финансового результата или автоматического fallback.

Launcher рассчитан на текущую вложенную структуру worktree и прежний UI venv. В другом размещении нужно явно задать доверенные `KP3_DESKTOP_CONTEXT` и `KP3_DESKTOP_HISTORY`, использовать проверенный отдельный UI Python и `python -m streamlit run app_kp3/desktop_app.py --server.address=127.0.0.1`. Для SourceViewer нужен прежний локальный Poppler; его отсутствие — техническая неготовность, а не отсутствие строки PDF.

UI entry/CSS/financial helpers не менялись на17: сохранена реальная CUA-проверка предшествующей UI-версии и выполняется её AppTest на кандидате. Новый launcher проверяется отдельно по фактическому процессу/HTTP/own identity; это не новая визуальная CUA и не новое исследование удобства.

## A/C и ограничения воспроизведения

`--profile A` или `--profile C` дополнительно проверяют 8 файлов pinned модели/сервера и выполняют только readonly probe localhost11435, без `/api/chat`, генерации, установки или запуска сервера. Недоступная модель даёт техническую ошибку `adapter_unavailable`, не финансовый отказ и не B. Сама возможность A/C доказана actual16 на неизменных core/prompt bytes, но её текущая готовность17 фиксируется отдельно.

Если явный запуск модели нужен позднее, применять прежний root/scripts/local_model.ps1, hidden loopback, Qwen3:4b digest359d7dd4…/Ollama0.40.15, cloud disabled, stop только own PID/path/starttime. Не считать ресурс присутствующим по имени. В fresh clone PDF/веса/exports/индексы/venv отсутствуют. Доверенную local map нужно восстановить из законно имеющихся exact-ресурсов и проверить SHA; произвольные пути/URL из финансового вопроса не становятся настройкой. Генерация нового manifest вместо проверки изменённого файла не является исправлением выпуска.

Доказательство нового каталога/публикации/прав/human_reviewed не создаётся: все 48 Fact остаются assistant_checked, human_reviewed=0, все 8 publication unknown/unproven. Подпись/fetched_at/HTTP/ZIP/synthetic дата не заменяют PublicationEvidence. Права первичных PDF/страниц/полного текста не подтверждены.

Оценённая версия16 сохраняет первые138actual/227nativechat и старые medians: B0.207/A2.459/C5.496s на известных40forms,32exactcells/28economiccontexts/8versions/2lineages. У A/C точностного преимущества на этом наборе не обнаружено. A tokens.unknown_records12 — два null token-поля у6 no-chat отказов, а не12 unknown requests; actualunknownrequests0. Первоначальные метрики/gold/raw не переписаны.

Новая папка с файлами manifest и явным resource rebinding проверяется как ограниченный restoration smoke на той же машине/окружении. Это не полный ZIP19, не установка с нуля на другом компьютере и не отправка20. Отчёт/слайды18 ещё не подготовлены; после самостоятельного промта18 работа останавливается.
