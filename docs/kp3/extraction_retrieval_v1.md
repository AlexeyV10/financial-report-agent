# КП3-06: извлечение кандидатов и поиск Evidence v1

Завершение10.11.2026, Europe/Moscow; работа началась09.11, поэтому доказательства сохраняются в `evaluation/kp3_06_2026-11-09/`. Это отдельный путь поиска по восьми exact-документам. Финансовые формулы07, parser русского вопроса08, сервис/агент/UI09–10 не реализованы.

## Два разных режима

**Prepared:** индекс48 проверенных Evidence из неизменённого `kp3_corpus_v1`. Поиск возвращает прежнее происхождение assistant_checked и digest Evidence; повторной проверки не выполняет. Это выбор уже подготовленного доказательства, не автоматическое извлечение числа.

**Automatic:** отдельный PDF-worker читает только локальный PDF и декларативный профиль. Готовые числа, Catalog, source-checks и gold ему не передаются. Он выделяет страницу, область, таблицу, строку и колонку, сохраняет заголовки, полный период, единицы, исходную запись, знак и координаты. Основной Python затем строит отдельный индекс кандидатов. Их статус — candidate; Evidence ID=null, новых Fact не создаётся. ID показателя/определения здесь — гипотеза по названию строки внутри подготовленного каталога, не автоматическое доказательство финансового смысла.

Метаданные группы/стандарта берутся из проверенного каталога05 и связываются с SHA PDF. Worker не заявляет автоматическое распознавание стандарта/организации или пригодность произвольного нового эмитента. Пригодность новой отчётности требует отдельной подготовки.

## Поддержанный профиль

Профиль `data/extraction/kp3_pdf_v1/`: горизонтальные русские финансовые таблицы выбранных макетов, годы20xx, отдельные страницы и развороты, две/четыре числовые колонки, полные годы по годовому заголовку и явно подписанные длительности3/6/9месяцев. Иная распознанная длительность может сохраняться как custom-кандидат, без допуска финансовой сопоставимости. Это не универсальный PDF-parser. Английские поисковые aliases не означают поддержку произвольной англоязычной отчётности.

Разворот определяется геометрией страницы; используются настоящие MediaBox/CropBox coordinates, включая ненулевой origin. Вертикальные боковые подписи не смешиваются с горизонтальными строками; повёрнутые финансовые таблицы не объявлены поддержанными. Многострочная подпись строки и координаты всей строки сохраняются. Границы колонок следуют из положения заголовков годов; групповые заголовки H1/9месяцев и отдельного квартала разбираются раздельно. Квартал не вычисляется вычитанием накопленных сумм.

Единицы читаются из заголовка, не из default ФосАгро. Запятая-разделитель тысяч, ASCII-пробел и однозначная десятичная запись различаются. Скобки сохраняют отрицательный знак. Неоднозначные десятичные запятые/смешанные разделители/NBSP и тире не превращаются в придуманные числа/нули. Положительное «использовано» не инвертируется автоматически и не сопоставляется signed net CFO по одному слову.

Отсутствующий заголовок/период, пустой текстовый слой или неподдержанный макет не повышаются до успешной таблицы. `not_recognized` означает отсутствие распознанного шаблона, а не отсутствие показателя в документе. Две таблицы прибыли ФосАгро2023/Q1 2025 остались неподдержанными без OCR; их ручная разметка05 сохранена. Ошибка парсера PDF возвращает технический error без ручного fallback.

## Поиск и фильтры

Новые модули — `document_extraction.py` и `retrieval_v2.py`; старый retrieval/CLI остаётся прежним. Новый поиск использует SQLite FTS5, нормализацию Unicode/ё/регистра и небольшой явный словарь ключевых слов/падежей. «Выручки», «операционной прибыли» и CFO проверены. Полный русский вопрос в Task не разбирается: это отдельный08.

SearchSpec `kp3-search-0.1` требует явные query, organization_id, group/legal_entity, standard, metric_id+definition_id, полные периоды, document_id+version_id, source_units, version_policy, snapshot/historical, as_of и top_k. Нет default организации/годов/версии. Неизвестные/дублирующиеся selections отвергаются, пропущенные поля дают awaiting_clarification. source_units — фильтр исходных единиц: RUB/тысячи не превращаются в RUB/миллионы, FX не выполняется.

Фильтры применяются вместе с FTS до top_k. Результаты не смешиваются в число и сохраняют отдельные document/version/SHA. Для original_period_documents comparative исключается. Сегежа2021 original и comparative2021 из2022 остаются разными версиями/масштабами, причина CFO-разницы не назначается. Подмена версии ресурса или выгрузки — техническая ошибка.

`found` сообщает о найденных записях, не о финансовом ответе. Проверяется покрытие запрошенных metric/period slots; недостаточное покрытие при непустом результате даёт `partial/incomplete_evidence_context` и список недостающего контекста. Это проверка slots, не oracle всех доказательств. Оценщик отдельно проверяет **все** обязательные Evidence и таблицы. Дубли одной физической ячейки не увеличивают попадания; конфликтующие копии отвергаются. Пустой результат не объявляется доказанным отсутствием финансовой строки. Во всех результатах financial_status=null.

## Неизменность и права

Индекс неизменяем: новая сборка требует новый путь. Сохранены SHA PDF, размер/страницы, код/config/environment worker, SHA его выгрузки, SHA SQLite и digest metadata. Подпись индекса также включает каталог, словарь/профиль поиска, код retrieval и его validation dependencies. Изменённый PDF/export/index/config/код/словарь/каталог не допускает старый результат. Это целостность, а не криптографическое доказательство авторства при подделке всех файлов одновременно.

PDF-worker получает ограниченный неизменяемый снимок байтов. Документы/текст/JSON — данные, не Python/shell/SQL-команды; запросы SQLite параметризованы. Worker не импортирует сеть/subprocess или оценочные данные. Полный текст/выгрузки/рендеры/индексы/выходы с первичным текстом остаются в исключённой tmp/. В Git только код, профиль, собственные минимальные targets/протоколы/хеши. Права на распространение первичных материалов не подтверждены.

Все8 публикаций unknown/unproven. Подпись/утверждение/fetched_at/HTTP metadata не подставляются в PublicationEvidence. Historical закрыт в обоих режимах; synthetic цены/даты к реальным отчётам не добавлялись. Human review, IFRS8/обзорные оговорки и сами Fact05 не изменялись.

## Запуск из worktree06

Основной Python3.14.7/SQLite3.53.4; worker — отдельный существующий CPython3.12.14/pdfplumber0.11.9/pdfminer.six20251230. Глобальные пакеты и UI-venv не менялись. Ниже карта tmp/local-resources.json должна указывать на реальные проверенные файлы05; повторно скачивать их не нужно.

```powershell
python -I scripts/check_kp3_retrieval.py
python -I -m unittest discover -s tests -v
```

Эти команды проверяют публичные входы/own synthetic tests, не извлекают реальные PDF. Для worker нужен явно выбранный PDF и новый выход в tmp/:

```powershell
& 'C:\Users\Value\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -I scripts/extract_pdf_v2.py '<проверенный локальный PDF>' tmp/extraction/new-export.json
```

Для всех выбранных документов подготовить явную карту document_id→новая выгрузка `tmp/export-resources.json`; worker никогда не получает values/targets. Затем выбрать режим индекса:

```powershell
python -I scripts/search_catalog.py index --kind prepared --catalog data/catalogs/kp3_corpus_v1/runtime_catalog.json --resources tmp/local-resources.json --db tmp/demo/prepared.sqlite
python -I scripts/search_catalog.py index --kind automatic --catalog data/catalogs/kp3_corpus_v1/runtime_catalog.json --resources tmp/local-resources.json --exports tmp/export-resources.json --db tmp/demo/automatic.sqlite
python -I scripts/search_catalog.py search --catalog data/catalogs/kp3_corpus_v1/runtime_catalog.json --resources tmp/local-resources.json --db tmp/demo/prepared.sqlite --spec data/examples/kp3_search_v01/direct_snapshot.json
```

Для automatic поиска дополнительно передать `--exports tmp/export-resources.json`. Пример полного комплекта — `data/examples/kp3_search_v01/all_three_snapshot.json`. Это явные примеры, не default API. Индексы/выходы не перезаписываются. Для нового воспроизводимого dev-прогона:

```powershell
python -I scripts/check_kp3_retrieval.py --resource-map tmp/local-resources.json --exports tmp/export-resources.json --work-dir tmp/new-dev-run
```
