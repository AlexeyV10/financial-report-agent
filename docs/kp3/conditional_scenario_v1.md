## Параметры и время

Capital:decimal string>0≤1e9 с точностью цента; allocation>0≤1; threshold_pct0…100; fixed commission0…1e6RUB с точностью цента; slippage_bps0…1000; lot integer1…1e6. Bool/float/NaN/exponent/лишние поля отвергаются. Window start — объявленный open, end — объявленный close; decision в окне и с timezone. Date-only publication становится доступной только со следующей полуночи в известной зоне; timestamp — с указанного момента. Неизвестность/дата после решения блокируют.

Entry — первый объявленный session open **строго после** decision; при decision ровно на open используется следующий. После закрытия/в выходной по собственному календарю выбирается следующий open. Exit — close конца окна. Никакой продажи по ещё не известной цене, промежуточной подстановки last-price или открытия за пределами окна. Все необходимые mark prices должны присутствовать; недостающий price/no future open/неподходящее окно дают blocked, без частичного ledger/PNL.

## Журнал и арифметика

У каждой сделки и отметки сохранены raw/effective price, объём, gross, commission, slippage_cost, cash, quantity, equity. Все вычисления в сервисе, Decimal80, денежные списания/остатки/equity до цента HALF_UP. Buy effective=raw×(1+slippage_bps/10000), sell effective=raw×(1−slippage_bps/10000). Лот округляется вниз по gross budget floor-cent(min(capital×allocation,capital−fee)); комиссия отдельно. Fee только при ненулевой сделке. Cash/quantity не отрицательны, leverage/short запрещены, позиция закрывается. Невозможная exit commission блокирует весь план атомарно. Нулевой доступный объём — завершённый no_trade/insufficient_for_lot с сохранёнными деньгами, без комиссии.

Cash benchmark — те же начальные деньги/окно, без процентов. Hold benchmark — та же доля/допустимый entry/exit и расходы, но обязательное условие входа вместо финансового сигнала. Это объявленное сравнение удержания с одинаковой экспозицией, не рынок. Cost checks дополнительно фиксируют quantity, чтобы изменение количества не подменяло влияние расходов.

Equity=cash+quantity×raw mark price в каждой объявленной точке; initial capital включён в running peak. Max drawdown=max((running_peak−equity)/running_peak), неотрицательный exact Fraction ratio и HALF_UP2 percent с датами peak/trough. Это метрика сценария12, не новая операция словаря04/калькулятора07. Независимый evaluator использует Fraction/integer cents и отдельный Decimal80 контроль; runtime не импортирует reference/gold. Runtime result validation повторяет стабильный сценарный результат по текущему контексту, это отдельная проверка целостности, не независимый эталон.
