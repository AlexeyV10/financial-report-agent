# Рабочий стол «Отчёт», версия 1

Пользователь выбрал первый предложенный вариант интерфейса. Реализация — отдельная задача КП3-UI после КП3-16. Это не выполнение КП3-17 или КП3-18.

Светлый фон, белые карточки, зелёный акцент, постоянная боковая навигация. На широком экране вопрос слева, результат справа; на узком — друг под другом. Основная кнопка «Проверить и рассчитать» находится сразу после вопроса. Технические сведения вынесены в раскрываемые блоки.

## Пользовательский путь

1. В «Анализе отчётности» написать вопрос или выбрать «Заполнить поля». Компания, период, версия и режим не получают скрытых значений. Для демонстрации можно явно нажать «Заполнить пример».
2. Указать условия или ответить на предложенные уточнения. Поддержка свободного текста ограничена грамматикой parser08; неоднозначная формулировка может потребовать выбора операции. Заполненные поля формы дают явный путь для всех пяти зарегистрированных операций.
3. Нажать «Проверить и рассчитать». По умолчанию выбран и подписан фиксированный поиск и расчёт B без модели. A/C выбираются явно в дополнительных настройках и используют прежние настоящие адаптеры; недоступная модель не заменяется B.
4. Рядом с ответом увидеть исходные значения, полные периоды, единицы, сравнительную роль базового числа. «Посмотреть источник» раскрывает строку, колонку, PDF/печатную страницу и ограничения. «Открыть страницу отчёта» открывает локальную страницу exact-ресурса после проверки SHA.
5. «Скачать ответ» предлагает собственный JSON или Markdown через прежнюю проверяемую выгрузку13. PDF и полные страницы не включены. Повторный такой же запрос открывает сохранённый снимок. «Рассчитать ещё раз» создаёт новую попытку после следующего нажатия расчёта.

Смена условий скрывает старый результат и отзывает старые ссылки источников/выгрузки. Исходный вопрос не переписывается; явные выборы передаются как уточнения08. Ложная предпосылка, её проверка и невыполненное причинное «почему» сохраняются. При уточнении, отказе или технической ошибке числового результата нет.

Другие разделы:

- «Документы» — восемь существующих PDF-версий, фильтр компании и проверка готовности файла/поиска. Восстановление допускается только для зарегистрированной exact-версии прежней функцией13, без расширения каталога.
- «История» — собственные сохранённые ответы/сценарии. Открытие помечено как снимок: без нового расчёта или вызова модели.
- «Учебный сценарий» — прежний сервис12 с явным выбором искусственных данных или проверки готовности реального источника. Искусственный результат 10000→10098 ₽ не является доходностью рынка. Реальная готовность остаётся заблокированной.
- «Как это работает» — короткая инструкция, границы показателей и диагностика модели без генерации.

## Код и запуск

Новый entry point — `app_kp3/desktop_app.py`, стили — `app_kp3/desktop.css`, подписи и адаптер явных полей — `desktop_presentation.py`. Финансовые вычисления, поиск, допуски, история, выгрузки и просмотр страниц вызывают неизменные сервисы06–13. Старый `app_kp3/product_app.py` и неопубликованный корневой UI сохранены.

На текущем компьютере worktree расположен в `tmp/kp3-ui-worktree`. Из него:

```powershell
& scripts/desktop_ui.ps1 start
& scripts/desktop_ui.ps1 status
```

Адрес: <http://127.0.0.1:8521/>. Для остановки только собственного процесса: `scripts/desktop_ui.ps1 stop`. Launcher проверяет PID/путь/время запуска, работает скрыто и слушает localhost. Другие запущенные интерфейсы не останавливаются.

Использован уже существующий корневой `tmp/kp3-ui-cpython312/Scripts/python.exe`: CPython3.12.14, Streamlit1.67.0, Pandas3.1.1. Это отдельный UI venv; основной Python3.14.7/SQLite3.53.4 не менялся. Новых пакетов нет. Launcher рассчитан на текущую структуру worktree; наличие venv и источников в свежем clone не предполагается.

При ручном запуске на подготовленном окружении задать `KP3_DESKTOP_CONTEXT` на доверенный service-context JSON и `KP3_DESKTOP_HISTORY` на собственную исключённую tmp-папку, затем запустить `python -m streamlit run app_kp3/desktop_app.py`. Контекст содержит только прежние runtime catalog/dictionary/admission/bindings/source checks/resource map и prepared index. Пути/URL из вопроса не используются как команды.

В текущей tmp подготовлены byte-identical копии восьми export06 и новые prepared/automatic SQLite индексы. Их SHA совпадают с замороженными14. Полные PDF/текст/индексы/exports/первичные страницы остаются только локально. Модель после16 не запускалась.

## Проверки и ограничения

778/778 unit (760 прежних +18 новых), 15/15 отдельных Streamlit AppTest, checkers03–14/старые gold04/07/corpus05/5 legacy CLI прошли. Первые ошибки и реальная эскалация WinError5 сохранены, отказ sandbox не обходился. Две ошибки дополнительных тестов исправлены по фактической подписи и объявленной грамматике; parser08 не расширялся.

Реальный браузер: расчёт +33,64%, открытие источника PDF5/printed1, собственные JSON/Markdown, повторный запуск, смена компании, уточнение компании, мобильное меню и документы. На360 px нет горизонтальной прокрутки; на1280×720 вопрос и ответ расположены рядом. Временный viewport сброшен, новая вкладка оставлена открытой. Download-event автоматизации завис, хотя файл скачался: успех подтверждён фактическими байтами файла, а не событием. Скриншоты собственных экранов и протокол — `evaluation/kp3_ui_2026-11-10/`.

Это известные разработчику инженерные случаи. Пользовательских интервью/исследования удобства не было. Новое качество модели/рынка и следующий benchmark не заявляются. Заморозка14 (134 файла/28 ресурсов), 138 raw16 и старые результаты сохранены; replay16 побайтово совпал.

Каталог прежний: 48 assistant_checked Fact/Evidence, human_reviewed=0, восемь публикаций unknown/unproven. Исторический/реальный торговый ответ закрыт. Права первичных документов не подтверждены. OP двух групп имеет разный отчётный состав, Segezha CFO original/comparative не объявлены эквивалентными. Новых источников, формул, OCR, разметки или допусков нет.
