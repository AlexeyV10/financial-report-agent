Облачный провайдер и платный бюджет не подключались. Фактические результаты — `evaluation/step9_2026-11-09/report.json`; ранние неудачные прогоны также сохранены.

## Чем отличаются A, B и C

| Вариант | Что происходит | Состояние |
|---|---|---|
| A: простой RAG | Один поиск и свободный ответ модели по найденному контексту | Только описанная линия будущего сравнения; не реализована и не измерена на этом шаге |
| B: фиксированный процесс | Проверенный запрос → поиск → прежние факты → тот же калькулятор → валидированный текст | Прежний `scripts/assistant.py` сохранён побайтно |
| C/mock | Контроллер получает решения детерминированного имитатора, проверяет их и исполняет инструменты | Проверка протокола, зависимостей и лимитов; не языковая модель |
| C/LLM | Настоящая Qwen3 4B получает наблюдения и выбирает действие в структурированном JSON | Реально запущена локально; выбранные действия, токены и исходы сохранены |

Модель не пишет финальный финансовый текст: его формирует прежний renderer после прежних валидаторов. Свобода агента сейчас мала: один документ, показатель и пара лет; он выбирает поисковые ключи/размер выдачи, порядок запросов фактов и дальнейшее действие в заданных зависимостях. Это учебный агент для выбора инструментов, не универсальный финансовый аналитик. История решений передаётся следующему вызову модели. Нет нескольких агентов, обучения или сервера проекта в интернете.

Выбрана собственная оркестрация на стандартном Python: четыре действия и явное состояние помещаются в одном модуле. Сторонний фреймворк потребовал бы дополнительной зависимости и проверки тех же финансовых правил; измеренного преимущества фреймворков нет. Решение можно пересмотреть при расширении задачи.

## Запуск на этом компьютере

Из корня проекта, PowerShell **7.4 или новее** (используется параметр Start-Process -Environment):

```powershell
.\scripts\local_model.ps1 start
```

```powershell
python scripts\agent_assistant.py --adapter ollama --trace output\agent-trace.json --save output\agent-answer.txt
```

Фиксированный B работает отдельно, без модели:

```powershell
python scripts\assistant.py
```

Явный mock:

```powershell
python scripts\agent_assistant.py --adapter mock
```

```powershell
python scripts\agent_assistant.py --adapter mock --mock-first-results 1
```

Последний пример специально начинает поиск с одного результата. Имитатор видит неполное покрытие, расширяет выдачу до пяти и завершает за шесть решений. Это предусмотренная ветка mock, не измерение способности LLM исправлять поиск.

Исторический режим и недостаточная выдача:

```powershell
python scripts\agent_assistant.py --adapter ollama --mode historical --as-of 2025-02-14T10:00:00+03:00
```

```powershell
python scripts\agent_assistant.py --adapter ollama --results 1
```

При неизвестной публикации ожидается `missing/publication_unknown`; прямой источник, snapshot и mock вместо этого не включаются. При ограничении top-1 нет обоих Evidence. Полный вывод/фактический исход модели смотрите в отчёте: технический сбой агента не приравнивается к корректному финансовому отказу.

`--source manual` отдельно выбирает прежний реестр без текущей проверки PDF/индекса. Это пользовательское решение, не автоматический резерв. Другие поля и уточнения сохранены из `UserQuery`. Новая команда не понимает произвольный русский вопрос. Exit code 0 — завершённый валидированный ответ/финансовый отказ; 1 — уточнение; 2 — техническая ошибка; 3 — лимит вызовов/времени.

```powershell

```

```powershell

```

Скрипт остановки проверяет путь и время создания процесса по своей записи. Он не останавливает все процессы Ollama и не трогает чужой сервер. Автозапуск Windows и глобальные переменные не добавлены.

## Разрешённые действия и состояние

`src/financial_assistant/agent.py` содержит схемы TOOLS, контроллер, MockAdapter и доверенную обёртку ToolRuntime; `local_model.py` — сменяемый реальный адаптер. SDK-пакетов не добавлено. Используется официальный [POST /api/chat](https://docs.ollama.com/api/chat) с [JSON schema в format](https://docs.ollama.com/capabilities/structured-outputs), stream=false, think=false, temperature=0, num_ctx=8192. Это JSON-протокол вызова наших инструментов; нативный tool_calls-протокол оказался неуспешным в начальном опыте и не выдаётся за финальную реализацию.

| Действие | Аргументы | Проверка/результат |
|---|---|---|
| search_evidence | query: строка до 160 символов; top_k: целое 1…установленный максимум | Только связанный документ/версия и mode/as_of. Проверяются исходный PDF/индекс и метаданные кандидатов |
| get_verified_fact | fact_id из каталога текущих двух входов | После поиска в search; нет значения без нужной ссылки, допустимой публикации и прежней проверки. Кандидат остаётся unavailable |
| calculate_growth | annual_growth_v1, previous_fact_id, current_fact_id | Запрошены оба факта; ID и порядок совпадают с контекстом. Прежний calculate_from_retrieval либо явный calculate_metric |
| finish | result_id из калькулятора | Повторная валидация и прежний render_financial; поля text/числа от модели запрещены |

Контекст вычисляется из проверенного `UserQuery` и полного ручного bundle. Компания, стандарт, документ/хеш, годы, mode/as_of и источник связаны с запуском. Модель не может передать другой путь к файлу, URL, период, стандарт, код, Fact или команду брокеру. `context_id` — хеш канонического JSON; это идентификатор целостности контекста, не криптографическая авторизация внешнего пользователя.

Полученные hits остаются кандидатами. В модель и trace попадают только их идентификаторы, версия, страница/сторона и ссылки на прежние Evidence; body/цитаты/инструкции источника туда не передаются. Перед выдачей Fact проверяются document/entity/version/hash/локаторы/review; калькулятор затем повторно проверяет связь Evidence. Числа поступают только из прежнего ручного реестра. Целевой фрагмент определяется покрытием двух Evidence, а не первым рангом.

Поиск должен предшествовать запросу фактов, оба запроса — расчёту, расчёт — finish. Нового поиска после выдачи фактов/расчёта нет: расширять/переформулировать запрос надо до их получения. Выдача последнего поиска заменяет предыдущую; удобные фрагменты разных запросов не объединяются молча. Для отсутствующего/неоднозначного входа контроллер возвращает прежний отказ выбора без обращения к модели и явно помечает `preflight_refusal`.

У результата контроллера отдельный `status`: completed, clarification, preflight_refusal, limit_exceeded, timeout, adapter_unavailable или error. `completed` может содержать финансовый missing/conflict/unsupported. Не путать эти статусы с Answer v0.1. Прежние контракты/финансовая арифметика не изменены.

## Лимиты и журнал

Лимиты — инженерный выбор, не найденный оптимум: **6 решений**, включая finish, невалидные вызовы и повторы; **180 секунд** на запуск, **90 секунд** на одно ожидание с учётом холодной загрузки. Ответ модели ограничен **256 выходными токенами**, контекст Ollama — 8192 токенами. Представленный JSON-наблюдение — до 32768 байт, summary инструмента — до 8192, действие — до 4096. Локальный транспорт дочернего процесса — до 262144 байт; это не разрешение передать полный текст модели.

Повтор идентичного успешного действия не выполняет инструмент заново и расходует попытку. Ложная схема/версия/ID/формула/порядок/состояние может быть исправлена только в оставшихся попытках. Превышение размера не приводит к скрытому усечению. При ошибке данных, timeout или недоступности модели нет silent fallback.

Ожидание адаптера и read-only инструментов вынесено в завершаемые дочерние процессы. После timeout результат не принимается, инструменты из позднего ответа не запускаются. Проверки deadline происходят до/после операций; к пределу возможна небольшая добавка на завершение процесса. Адаптер — доверенный код проекта; multiprocessing не объявляется песочницей для произвольного чужого Python. Код, сгенерированный моделью, не исполняется вообще.

Trace содержит UUID, фактические времена/длительности, контекст, хеш bundle/документа/модулей/схемы инструментов/промпта, версии контроллера/адаптера/модели/сервера, параметры/лимиты, разрешённые аргументы, краткие наблюдения, ошибки, причину остановки и конечный финансовый статус. Отклонённые произвольные ответы фиксируются хешем/кодом, без сырого текста/исключения провайдера. Валидный короткий поисковый запрос записывается для воспроизведения; полных hits и секретов нет. Скрытые рассуждения модели не запрашиваются и не сохраняются в отчётах.

`--trace` разрешён только в .json под output/ или tmp/, `--save` — в .txt там же. Нельзя затереть этой командой исходный JSON/PDF/код. Проверяемые отчёты в evaluation/ создаёт отдельный скрипт приёмки, а не модель.
