## Минимальный запуск без модели и первичного PDF

Нужен Python. Код основных режимов использует стандартную библиотеку; отдельная установка pip-пакетов для этих команд не нужна. Ранее проверен Windows/MSYS2 CPython3.14.7; результат проверки новой Git-копии записывается отдельно, другие платформы автоматически не объявляются проверенными.

~~~powershell
python -I scripts/run_local.py fixed --source manual
~~~

Это прежняя ручная разметка, без нового поиска или проверки PDF. Ожидаются выручка группы «ФосАгро» по МСФО440304/507689 млн RUB за полные2023/2024, изменение+67385 и рост+15,30%, формула, локаторы и ограничения.

~~~powershell
python -I scripts/run_local.py scenario
~~~

Это отдельные вымышленные цены, даты и факты:10000→10098 RUB с комиссиями2, а не результат торговли на рынке.

~~~powershell
python -I scripts/run_local.py scenario --case real-source
~~~

Ожидается запрет publication_unknown без сделок и доходности. Настоящая публикация выбранной PDF-версии неизвестна.

Для проверки кода при его изменении сначала создать пустую рабочую tmp/, затем выполнить тесты:

~~~powershell
python -c "from pathlib import Path; Path('tmp').mkdir(exist_ok=True)"
~~~

~~~powershell
python -I -m unittest discover -s tests -v
~~~

Остальные зависимости, настоящий локальный агент, явный mock, поиск и восстановление архива описаны в docs/local_demo.md. Первичный PDF, индекс, Ollama и веса модели в репозиторий не входят. Клонирование не устанавливает их и не запускает модель. Отсутствие ресурса не разрешает скрыто подменять LLM имитатором.

## Как вносить изменения

Ветка main — общая исходная версия. Для конкретной задачи создать отдельную ветку. Ветка — собственная линия изменений; pull request — предложение объединить её с main. Это помогает видеть разницу файлов и сохранять историю, не означает обязательную приёмку другими формальными участниками.

Перед началом новой задачи при чистой рабочей папке:

~~~powershell
git switch main
~~~

~~~powershell
git pull --ff-only
~~~

~~~powershell
git switch -c feature/source-adapter
~~~

После работы посмотреть изменения и добавить только нужные файлы:

~~~powershell
git status
~~~

~~~powershell
git diff
~~~

~~~powershell
git add путь/к/изменённому/файлу
~~~

~~~powershell
git commit -m "Краткое описание изменения"
~~~

~~~powershell
git push -u origin feature/source-adapter
~~~

Затем открыть репозиторий и создать pull request этой ветки. Не перезаписывать общую историю через force push. При конфликте сохранить обе работы и разрешить его по смыслу; не удалять чужие изменения автоматически. Не включать в коммит посторонние правки.

## Что хранится в Git

Собственный код, минимальная разметка, свои искусственные данные, тесты, документация, выбранные доказательства, готовые DOCX/PPTX и два собственных PDF КП2. Четыре ранее проверенных ZIP с receipt сохранены как неизменяемые снимки; их имена разрешены в .gitignore явно. Старые ZIP — история, текущий кодовый снимок — kp2-local-step13-v1-2026-11-09.zip, пакет материалов — kp2-materials-step14-v1-2026-11-09.zip.

Первичная отчётность, её полные страницы/текст/индекс, модели, бинарники, ключи, токены, .env и личные выгрузки исключены. Не добавлять их с git add -f. Приватность репозитория не заменяет право распространять чужие документы. .gitattributes сохраняет исходные байты файлов: замороженные эталоны и manifests проверяют SHA-256, поэтому автоматическая смена LF/CRLF нарушила бы проверку.

Метрики остаются малыми: один числовой dev-вопрос B/C1/1, отказыB2/2vsC1/2, поддержаны3/10financial, известный Ctop1 call_limit — ошибка. Новое размещение и новый участник не увеличивают знаменатель и не подтверждают общее качество модели. Публикация на GitHub не является сдачей КП2 в форму курса.
