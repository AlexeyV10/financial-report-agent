# Шаг 10: отдельный искусственный виртуальный сценарий

09.11.2026. Это детерминированная проверка арифметики и времени на собственных вымышленных входах. Модель, биржевой API и брокер не участвуют. Реальная отчётность «ФосАгро» в этот набор не подставляется.

## Запуск

Из корня проекта в PowerShell:

```powershell
python scripts\simulate_scenario.py
```

```powershell
python scripts\simulate_scenario.py --save output\synthetic-scenario.txt --trace output\synthetic-scenario.trace.json
```

По умолчанию выбран явно помеченный **ИСКУССТВЕННЫЙ НАБОР / ВИРТУАЛЬНЫЙ СЦЕНАРИЙ**. Внутренние ID вводить не нужно. Все факты, группа, публикация, календарь и цены вымышлены. JSON можно явно выбрать через --fixture; ошибочный/пустой/настоящий набор не заменяется демонстрацией молча.

Отдельная проверка настоящего источника:

```powershell
python scripts\simulate_scenario.py --case real-source --as-of 2025-06-04T19:30:00+03:00
```

Она возвращает blocked/publication_unknown, пустой журнал и return_pct=null. Выбранный момент анализа не присваивается документу как публикация. Синтетические цены/даты к нему не присоединяются. У real-source нет параметра --fixture; у synthetic нельзя через --as-of молча заменить фиксированный момент решения — для варианта нужен явно изменённый искусственный JSON.

Exit code 0 — завершённый виртуальный сценарий либо объяснимый запрет; 2 — ошибка схемы/входов/параметров/результата/сохранения. --save разрешён только в .txt под output/ или tmp/, --trace — в .json там же. Нельзя затереть этими параметрами настоящий bundle, PDF или код. В stdout нет traceback, сырого кода источника или скрытого резервного режима.

## Зафиксированное правило и ручной контроль

До первого исполнения сохранён data/synthetic/frozen_rule_v1.json с хешем fixture и параметрами. Порог/доля/расходы выбраны для учебной проверки; оптимизации результата нет. Генератор prepare_synthetic_fixture.py создаёт файл с нуля, не читает финансовый JSON эмитента и отказывается перезаписывать существующий fixture.

| Параметр | Правило версии 1 |
|---|---|
| Источник сигнала | Собственная условная группа, выручка 100 → 120 млн RUB за полные 2023/2024; рост берётся из прежнего calculate_metric, не считается заново |
| Условие | Рост строго больше 10%; при равенстве покупки нет |
| Действие | Одна покупка, удержание до последнего закрытия окна, одна продажа |
| Капитал/актив | 10 000 RUB; один вымышленный SYNTH_ASSET; без плеча/шорта |
| Доля | До 20% первоначального капитала по номиналу исполнения **без комиссии**; бюджет округлён вниз до копейки |
| Количество | Целые лоты; lot_size=1; округление вниз по фактической цене исполнения |
| Комиссия | 1 RUB за каждую операцию, сверх ограничения номинала; требуется достаточно cash |
| Проскальзывание | В базовом примере 0 б.п.; в вариантах повышает цену покупки/понижает цену продажи |
| Время | Вымышленная публикация 04.06.2025 19:00 +03:00; решение 19:30 после вымышленного закрытия в 18:00 |
| Исполнение | Первое указанное открытие **строго после решения**: 05.06.2025 10:00 +03:00 |
| Закрытие | Последнее закрытие заданного окна: 09.06.2025 18:00 +03:00 |

Независимый буквальный контроль из задания пользователя хранится в manual_expected_v1.json. В тестах/отчёте он проверяется через Fraction, отдельно от Decimal-реализации:

| Операция | Номинал | Комиссия | Деньги после | Позиция |
|---|---:|---:|---:|---:|
| Начало | — | — | 10 000 | 0 |
| Купить 20 × 100 | 2 000 | 1 | 7 999 | 20 |
| Продать 20 × 105 | 2 100 | 1 | 10 098 | 0 |

Искусственное изменение капитала +98 RUB / +0,98%, комиссии 2 RUB. Это не рыночная доходность. Во время удержания показаны цены 101, 102, 98, 103 и стоимость cash + quantity × текущая цена; по ним дополнительные сделки не создаются. Комиссии включены в cash, проскальзывание включено в цену исполнения и не вычитается повторно.

Оценки/платежи округляются до копеек ROUND_HALF_UP, цены исполнения сохраняют вычисленную точность. Число лотов и бюджет доли округляются вниз. Если выбранный размер вместе с комиссией не помещается в cash, результат blocked/insufficient_cash: количество не уменьшается задним числом ради успешного исхода. Нулевой доступный лот даёт blocked/zero_lot. При ошибке исполнения весь виртуальный план считается незавершённым, без частичных сделок/доходности в результате.

Сравнения используют то же окно, актив, цены, начальный капитал, лимит номинала, лот и расходы. Cash_no_interest не торгует и остаётся 10 000 RUB. Buy-and-hold входит на первом допустимом открытии после того же момента решения, независимо от порога, и закрывается в конце. В базовом примере он совпадает с условным правилом: 10 098 RUB. При пороге 20% правило не торгует и остаётся в деньгах, а удержание всё равно покупает. Это разные определения сравнения, не преимущество стратегии.

## Даты, календарь и источник

Календарь — собственные четыре вымышленные дневные сессии 4, 5, 6 и 9 июня; выходные отсутствуют. Это не выгрузка календаря Мосбиржи. Цена требуется точно на каждом открытии/закрытии, в порядке времени, без дублей и лишних моментов. Отсутствие не заполняется другой/будущей/предыдущей ценой. Неизвестные корпоративные события, дивиденды/сплиты, валюта/актив/версия вне учебного договора отклоняются.

Используется прежний available_from: timestamp сохраняет точный момент, date без времени даёт консервативную границу следующего дня в Europe/Moscow; unknown или несвязанная версия не дают допуска. Решение должно быть не раньше доступности факта. Исполнение — первое открытие строго позже решения; intraday/совпадение с открытием также требуют следующего открытия. Выходной переводит исполнение на следующую указанную сессию. Часовой пояс обязателен; эквивалентный UTC timestamp поддержан, наивный не принимается. Публикация до конца годового периода отклоняется. Fetch/approval/конец периода не подставляются вместо публикации.

В data/synthetic/scenario_v1.json вложен отдельный FinancialBundle v0.1. Его schema требует PDF/page-поля; здесь document_type=synthetic_contract_fixture_not_a_pdf, а одна виртуальная таблица и номера страниц — поля совместимости, не утверждение о существовании PDF. Документ/группа/Fact IDs имеют собственные synthetic-идентификаторы, URL example.invalid. SHA-256 и размер проверяются по собственному source_text, строки Evidence связаны с ним. Никто не скачивал этот «отчёт» и не подтверждал его как отчёт эмитента.

Вымышленные publication/approval/release даты обозначены в provenance; fetched_at записывает реальный момент захвата авторского текста при создании fixture, не доказывает публикацию. assistant_checked означает техническую проверку определения/согласованности fixture. Human review/audit не выдуманы. Права confirmed относятся только к собственному искусственному тексту, не к настоящему PDF.

## Новый договор и прежний gate

ScenarioRequest/SyntheticScenarioResult **v0.1** — отдельные записи. Код simulation.py не меняет contracts.answer/available_from, FinancialToolResult или Answer v0.1. Внутренний финансовый запрос принудительно historical_as_of с внешним decision_at; модель/JSON не могут выбрать snapshot вместо этой проверки.

Старый Answer.scenario_gate остаётся blocked с прежними причинами calendar_and_prices_missing / simulation_not_implemented: в этот финансовый контракт календарь и цены не передавались, simulator admission в нём не реализован. Он не переименован в ready и не выдаётся за общий текущий статус всего проекта. Новая оболочка сохраняет его как legacy_gate и допускает **только свой искусственный** набор после отдельной полной проверки публикации/финансового результата/календаря/цен/денег. Неизвестная публикация/финансовый отказ не игнорируются. Real-source остаётся диагностикой, никогда не открывает реальный сценарий.

Результат содержит status completed/blocked/error, reason_code, request_sha256, финансовый результат либо null, eligibility, scenario (ledger/суммы/расходы/конец) и comparisons. При blocked/error scenario/comparisons=null; это не нулевая доходность. Renderer заново валидирует результат относительно входов перед показом. Сравнение канонического JSON различает bool/целые/float: подмена нулевой позиции на False тоже отвергается. Дефект воспроизведён новым тестом до исправления; доказательство — type-tampering-before-fix.txt.

Trace CLI содержит UUID, реальные начало/конец/длительность, тип случая, хеш входов, версии схем/формулы/кода и результат/журнал. model_calls=0 — факт отсутствия модельных вызовов этого процесса. Полного первичного документа/индекса/hits/секретов/произвольного кода в нём нет.
