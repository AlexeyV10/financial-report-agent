# Шаг 8: понятный пользовательский путь

Это протокол шага 8; текущие возможности — STATUS.md. На шаге 10 появилась отдельная искусственная симуляция (docs/simulation.md); в финансовом CLI обновлена только последняя фраза об отдельном запуске, числовые результаты/режимы/источники сохранены.

09.11.2026. Один локальный вход запускает ограниченный сценарий, живой поиск, получение прежних проверенных фактов, расчёт и понятный ответ по-русски. У пользователя больше не запрашиваются `fact_id` или `evidence_id`.

## Почему CLI

Для одного документа и одного проверенного вопроса выбран CLI: запускается одной командой в уже проверенном Python, не требует сервера, браузера, модели или новых пакетов. Он даёт воспроизводимую демонстрацию шага 8. Streamlit мог бы упростить формы и раскрываемые панели, но сейчас добавил бы зависимость и отдельный запуск без изменения проверяемого содержания. Веб-интерфейс не создавался.

## Обычный запуск

Из корня проекта в PowerShell:

```powershell
python scripts\assistant.py
```

Без аргументов выбран **явный предустановленный сценарий**: группа «ФосАгро», МСФО, выручка за полный 2024 год относительно полного 2023, анализ выбранной версии, локальный поиск. Все эти параметры напечатаны в вопросе и режиме. Это шаблон запроса, а не понимание произвольной русской фразы языковой моделью.

Имеющийся ответ можно сохранить как текст:

```powershell
python scripts\assistant.py --save output\user-answer.txt
```

В ответе: оба полных интервала, суммы 440 304 и 507 689 млн руб., абсолютное изменение +67 385 млн руб. и +15,30%, формула и подстановка, правило отображения/округления, два локатора со столбцами 2023/2024, PDF 4 / печатная 320 / страница формы 1, строка, заголовок таблицы, сторона разворота, URL и версия документа. Калькуляция не выполняется в renderer: он форматирует уже проверенный результат, сохраняя значащие десятичные знаки и знак числа. Источники — сравнительные столбцы одной выбранной версии, не исходные публикации каждого года.

Для основной команды нужны `tmp/pdfs/phosagro-2024-ru.pdf` и `tmp/retrieval/document.sqlite`. Если источник/индекс отсутствует или версия не совпадает, выводится техническая ошибка с действием для исправления, а не отсутствие финансового показателя. Индекс автоматически не перестраивается, PDF не скачивается. Его подготовка описана в `docs/retrieval.md`.

## Ввод и выбор режима

```powershell
python scripts\assistant.py --company ФосАгро --scope группа --standard МСФО --metric выручка --year 2024 --compare 2023
```

В этой версии поддержан только данный сценарий. Указанные явно неизвестные/пустые/неоднозначные компания, показатель, стандарт, границы или годы дают **«Уточните запрос»**. Другой период не заменяется 2024/2023. Девять месяцев и квартал не переименовываются в год. Поддержанные формы названия компании — «ФосАгро» и «группа ФосАгро», без учёта регистра; синонимы стандарта МСФО/IFRS и показателя выручка/revenue. Общего NLP-парсера нет; `--question` с произвольным текстом не поддержан и не запускает текущий пример молча.

Исторический режим:

```powershell
python scripts\assistant.py --mode historical --as-of 2025-02-14T10:00:00+03:00
```

Для текущего PDF получается отказ: неизвестно время публикации именно этой версии. Момент передаётся без подмены через поиск и калькулятор. `--as-of` в snapshot вызывает уточнение, а не игнорируется; historical без даты или часового пояса тоже требует уточнения. Режим не переключается автоматически.

Отдельный явный ручной режим:

```powershell
python scripts\assistant.py --source manual
```

Он использует прежний ручной реестр и прямо сообщает, что текущие поиск/проверка PDF не выполняются. Он может работать без PDF/индекса. При ошибке search этот режим **не включается автоматически**. Исторический запрет остаётся и в manual. Это не новый анализ первоисточника.

Дополнительные параметры: `--results 1…10`, `--pdf`, `--db`, `--bundle`, `--save`. Первые три нужны для локальных данных/диагностики; ID инструментов не становятся пользовательским вводом. `--help` описывает их. При `--results 1` первое примечание не покрывает обе ссылки, поэтому числового ответа нет; с пятью результатами используется второй фрагмент.

Сохранение разрешено только в `.txt` внутри `output/` или `tmp/`. Это не позволяет командой `--save` затереть PDF, SQLite, JSON-реестр или исходный код. При ошибке сохранения успешный сохранённый отчёт не заявляется. Полный текст отчётности и hits не сохраняются в пользовательском отчёте: только минимальные факты/локаторы и собственное объяснение/расчёт.

## Внутренний путь и совместимость

`UserQuery` в `src/financial_assistant/user_path.py` хранит компанию, границы, стандарт, показатель, годы, источник, mode/as_of. Проверка поддержанного сценария предшествует вызову инструментов. Выбранный bundle должен относиться к этой группе, стандарту и области периодов; другой набор не подставляется под прежний вопрос.

Для каждого периода выбирается ровно один прежний Fact по показателю/интервалу. Отсутствие или несколько кандидатов возвращают отказ без выдуманных ID и выбора первого. Затем используются прежние `search_index` → `calculate_from_retrieval` → `validate_financial_result`. В ручном режиме — `calculate_metric` и тот же валидатор. `render_financial` проверяет весь финансовый результат перед показом. Подменённый процент/источники/предупреждения не отображаются как ответ.

Первый hit — примечание, а оба необходимых Evidence находятся во втором; пользовательский путь это сохраняет. Текст кандидатов не используется для новых чисел и не попадает в пользовательское объяснение. Два локатора в ответе — это два прежних Evidence одной таблицы, не заявление о двух независимых источниках или людях.

`run_user_query` возвращает UserResponse v0.1: `query`, `status`, `reason_code`, `text` и минимальный `financial_result` либо null. Это отдельная оболочка представления; FinancialToolResult/Answer v0.1 и формула не менялись. `clarification` — состояние пользовательского ввода, не финансовый статус и не технический сбой.

## Отказы и диагностика

| Состояние | Показ пользователю | Exit code |
|---|---|---|
| answered | Числа, периоды, формула, обе ссылки, режим и ограничения | 0 |
| missing | Недостаточно подтверждённых данных/неизвестная публикация/обоих Evidence нет | 0 |
| conflict | Несопоставимость периодов/единиц/границ, неоднозначность | 0 |
| unsupported | Методика не применима, например неположительная база | 0 |
| clarification | Уточнить неподдержанный или неоднозначный запрос/дату | 1 |
| error | Техническая ошибка PDF/индекса/реестра/параметров/сохранения | 2 |

Отказ не выводит формулу с численным процентом, скрытый результат или ложный ноль. Нулевое текущее значение допускается инструментом и показывает −100%; отсутствие значения остаётся missing. На русском явно объясняются несовместимые единицы и неподдержанная неположительная база. В техническом сообщении нет traceback или сырых внутренних подробностей; причина и полезное действие даны по известному коду.

Ограничения показываются словами: ручное происхождение фактов, работа ассистента, отсутствие заявленной проверки пользователем, неизвестная публикация версии, неустановленные права, аудиторская оговорка и предел точности опубликованных сумм. Последняя фраза сообщает, что искусственный сценарий запускается отдельно, финансовый ответ не разрешает торговлю и не является инвестиционной рекомендацией. Неизвестное новое предупреждение не отбрасывается молча. Числа не генерируются свободным текстом, историческая доступность не утверждается в snapshot.
