# Файлы для чистой виртуальной Windows — 11.11.2026

По просьбе пользователя выбран **Oracle VirtualBox 7.2.22 для Windows x64** и
официальный **Windows 11 Enterprise Evaluation 26H2 x64, English (United States)**.
Это установочные файлы для создания новой виртуальной машины. Готовая установленная
Windows ещё не создана, WIN-02B не принят. Статус загрузки и фактические хеши —
`evaluation/windows_vm_download_2026-11-11/downloads.json`.

VirtualBox подходит для проверки нашего Windows-приложения в отдельной чистой
системе. Oracle указывает поддержку Windows 11 x64 как хоста и гостя в
[руководстве](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/Introduction.html).
Базовый пакет доступен по GPLv3; необязательный Extension Pack не нужен и не скачан.
Установщик взят с [официальной страницы Oracle](https://www.oracle.com/virtualization/technologies/vm/downloads/virtualbox-downloads.html),
хеш сверен с [SHA256SUMS](https://download.virtualbox.org/virtualbox/7.2.22/SHA256SUMS),
подпись проверена штатным средством Windows.

Образ получен по публичной ссылке [Microsoft Evaluation Center](https://www.microsoft.com/en-us/evalcenter/download-windows-11-enterprise).
Microsoft предоставляет 90-дневную оценочную версию без ввода ключа продукта;
для подготовки и активации действуют опубликованные
[условия и инструкции](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise).
Они предусматривают регистрацию и вход с Microsoft account. Данные пользователя
не отправлялись, учётная запись не создавалась, регистрация/активация не выполнены.
Срок пробного использования не продлевался. Это не бессрочная лицензия.
Для ISO опубликована отдельная
[контрольная сумма Microsoft](https://support.microsoft.com/en-us/servicing/os/windows/docs/2026/09/verify-the-authenticity-of-a-windows-11-enterprise-evaluation-iso-file).

Бывший [адрес готовых Microsoft developer VM](https://developer.microsoft.com/en-us/windows/downloads/virtual-machines/)
сейчас перенаправляет к документации разработчика; готовый appliance по этому адресу
не получен. Чистая установка из ISO также позволяет не включать в гостя инструменты
разработки, которые помешали бы нашей проверке отсутствия глобального Python.

## Где находятся файлы

От корня проекта:

- `tmp/windows-vm-download-worktree/tmp/downloads/VirtualBox-7.2.22-175245-Win.exe`;
- `tmp/windows-vm-download-worktree/tmp/downloads/Windows11_Enterprise_Eval_26H2_x64_en-us.iso`.

Файлы остаются локально в исключённой `tmp/`; в публичный GitHub они не загружены.
ISO — образ установочного диска. Его нужно подключить к будущей виртуальной
машине, чтобы установить Windows внутри неё. На основной компьютер Windows из
этого образа не устанавливается.

## Следующий отдельный шаг

Сначала установить скачанный VirtualBox на хост. Это установка системных драйверов,
требующая прав администратора; пользователь пока поручил скачать файлы. Установщик
не запускался. BIOS, компоненты Windows, защита и сеть хоста не менялись.
Дополнительные Python bindings для управления VirtualBox не нужны.

Для нашего испытания без модели предлагаются начальные настройки гостя:

| Настройка | Предложение |
|---|---|
| ОС | Windows 11, 64 bit, новая установка из скачанного ISO |
| Память | 4096 МБ; перед запуском закрыть тяжёлые приложения |
| Процессоры | 2 виртуальных CPU |
| Диск | 64 ГБ, динамический VDI, локально вне OneDrive |
| Загрузка | EFI, Secure Boot, виртуальный TPM 2.0, I/O APIC |
| Папки и буфер обмена | Не подключать весь профиль/репозиторий хоста |
| Модель/Python/Git | В чистую Windows не устанавливать |

Это предложение для малого installer-теста, а не измеренные минимальные требования
полной программы с Qwen. На хосте около 16 ГБ RAM; доступная память меняется.
На момент подготовки было около 144,7 млрд свободных байт на C: до загрузки.
64 ГБ виртуального диска не резервируются целиком сразу, но рост и снимки надо
учитывать. Параметры EFI/TPM описаны в
[настройках VirtualBox](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/working-with-vms.html).

Хост сообщает HypervisorPresent=true, тогда как некоторые WMI-флаги VT-x/SLAT —
false. Это не доказательство выключенной настройки BIOS. Реальный запуск гостя
ещё не испытан. Для работы поверх существующего Hyper-V Oracle описывает
[использование Windows Hypervisor Platform](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/AdvancedTopics.html).
При ошибке сохранить точный текст и определить причину; не отключать защиту или
менять загрузочные параметры автоматически.

После законной регистрации/установки/активации Windows подготовить отдельную
обычную учётную запись без Administrators для самой приёмки. Административная
учётная запись для первоначальной настройки гостя — другая роль. При необходимости
русского озвучивания сначала штатно подготовить языковые/речевые компоненты гостя.
Зафиксировать фактические OS/build/.NET и происхождение; сделать чистый снимок
до установки нашего приложения. Отключать сеть для offline-проверки только у гостя.
Затем использовать уже готовый
[сценарий WIN-02B](../../spikes/windows_02b/RUNBOOK_RU.md) и прежний kit с неизменным
installer, без повторной подготовки пакета.

Нет установленных/запущенных VM, принятой доступности управления гостем, guest
measurements или install/uninstall результата. WIN-02 остаётся
`host_validated_clean_vm_pending`. Старый UI, ядро, Qwen и предыдущие этапы не менялись.
