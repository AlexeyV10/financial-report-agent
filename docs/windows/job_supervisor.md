# WIN-06 · Очередь длительных заданий на Windows

Диспетчер хранит задания одного выбранного vault и запускает по одному заданию
в порядке очереди. Повтор идентичного запроса возвращает его состояние. Тот же
ID с изменившимся запросом отклоняется. При явном повторе после отказа создаётся
новое задание со ссылкой на прежний ID. [Диспетчер](../../src/financial_assistant/job_supervisor.py).

Журнал сохраняет очередь, запуск, контрольные этапы прогресса, отмену, дедлайн,
сбой и публикацию. Технические события содержат коды без текста документа.
Прогресс нынешней учебной операции обозначает пройденные контрольные этапы,
поэтому он не предсказывает долю времени до завершения.

Принятый ответ привязывается к текущей попытке. Перед записью финального файла
диспетчер сохраняет ожидаемый SHA-256 ответа. При повторном открытии запись
`running` становится `interrupted`. После прерывания на фазе `committing`
завершение восстанавливается только при совпадении уже записанной квитанции.
Проверяются версия контекста и фактический SHA источника. Квитанция результата
и журнал остаются доступными в выбранном vault.

На Windows используется отдельный Job Object. Диспетчер присоединяет дочерний
процесс по полученному при его запуске дескриптору до передачи запроса. Дескриптор
Job Object не наследуется. При отмене, истечении срока и закрытии диспетчера
операционная система завершает связанные процессы. [Реализация](../../src/financial_assistant/windows_job.py),
[описание Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

## Воспроизведение проверки

```powershell
python -X utf8 -I -B -m unittest discover -s spikes/windows_06 -p test_job_supervisor.py -v
python -X utf8 -I -B spikes/windows_06/check_supervisor.py --runtime-build tmp/runtime-a --demo tmp/own-demo --out tmp/supervision-e2e
```

Прогон создаёт только собственные временные задания. Отдельный проверочный
worker запускает один принадлежащий ему дочерний процесс. Состояние обоих
проверяется по дескрипторам Windows. Контрольный процесс вне Job Object остаётся
жив. Установленный CLI с `--supervised` проводит фиксированный расчёт WIN-05 и
повторяет ранее сохранённый результат при том же ID без новой записи.
[Результаты](../../evaluation/windows_06_2026-11-19/supervision.json).

На Windows подтверждены завершение worker и его потомка при отмене, тайм-ауте
и принудительной остановке тестового диспетчера, а также восстановление состояния
`interrupted`. После раннего сообщения об успехе требование завершения процесса
сохраняется. По 10 тестов диспетчера прошли на обоих Python, включая FIFO, дедлайн,
поздний ответ, повтор и восстановление публикации по точному хешу. В первом
параллельном прогоне был отказ записи журнала. Повторные прогоны его не воспроизвели,
а причина осталась неизвестной.

Оконную очередь подключит этап оболочки. Журнал этой версии ограничен одним
владельцем выбранного vault. Следующий этап расширяет хранилище с помощью SQLite.
[Сценарий WIN-07](../../prompts/windows_07_vault_storage.md).
