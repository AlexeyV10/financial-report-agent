# ADR-D01: WPF с общим Python worker для следующего Windows spike

Дата: 11.11.2026. Статус: **принят для WIN-02 с явно открытыми проверками**.
WIN-01 завершён как сравнительный feasibility/ADR, не как готовый продукт.

Выбран основной UI **WPF + Python worker**. Предпочтительный Qt практически
испытан, но не прошёл текущую проверку: повторяются паузы обработки событий
695–760 мс, а собранный PyInstaller frontend не стартовал из-за DLL при импорте
QtCore. Это конкретные наблюдаемые причины fallback. Причина пауз не локализована;
не объявляем Qt в целом непригодным. Возврат к нему потребует отдельного
доказательства устранения обеих проблем, не нового выбора по скриншоту.

## Одинаковый узкий срез

Оба реальных native окна открывают собственный PDF через файловый диалог,
показывают native таблицу 10000 технических строк с сортировкой/выбором, страницу
и выделенную ячейку, прогресс/отмену/сбой и текстовую альтернативу. HTTP UI,
Streamlit и WebView в этом срезе отсутствуют. Общий renderer — pypdfium2 5.15.2,
фактический PDFium **159.0.8149.0@sourcebuild-toolchained**, не версия из памяти
или текущей документации. Qt PDF не используется.

Общий адаптер вызывает исходный `operating_margin_v1`: 18 / 120 × 100 = **15,00%**.
МСФО, группа, полный 2025 год, млн RUB, оба положительных значения проверены
по собственному оригинальному PDF. SHA: `c749435d1d445664dd5b28f54e6fd19f5fbcdb91d505e6ac112d1ba7f4715451`.
Неизвестная публикация остаётся неизвестной, `human_reviewer=null`.
Прежний synthetic admission сохранён: его record_id отдельно связан адаптером
с SHA/страницей/прямоугольником собственного PDF. Это не новый real-issuer
admission и не доказательство универсального импорта. Финансовые формулы в GUI/C#
не повторяются. `expected.json` — независимый oracle только для проверок.

## Среда и измерения

Windows 11 Pro 10.0.26200, Intel i7-14700HX (20 ядер/28 потоков),
16 873 545 728 байт RAM. Stock CPython 3.12.14 в новом отдельном окружении;
PySide6 Essentials/shiboken 6.11.3. WPF собран системным csc x64 и реально
исполнен на предустановленном **.NET Framework 4.8.1**, registry Release 533509,
CLR 4.0.30319.42000. Это не modern .NET SDK и не подтверждение private .NET.
Версия определяется по Release, отдельно от CLR.
[Таблица Microsoft](https://learn.microsoft.com/en-us/dotnet/framework/install/how-to-determine-which-versions-are-installed).

Три последовательных чередующихся запуска каждого source frontend на одной
машине; общий worker и собственный PDF одинаковы. Медианы окончательного final2:

| Величина | Qt | WPF |
|---|---:|---:|
| Внешний startup до ready | 0.514 с | 0.275 с |
| Idle сумма RSS дерева | 89.0 MiB | 130.2 MiB |
| Peak сумма RSS дерева | 261.3 MiB | 257.4 MiB |
| Сортировка и выбор таблицы | 25.1 мс | 60.1 мс |
| Отправка отмены | 1.0 мс | 0.8 мс |
| Максимальный наблюдённый gap, диапазон трёх запусков | 695–760 мс | 108–153 мс |

В обоих вариантах отменённый worker отсутствовал при проверке через 300 мс.
Первый startup Qt 0,514 с/WPF 0,315 с; последующие медианы 0,510/0,274 с.
Это первые/повторные процессы при неизвестном кэше ОС: **настоящий cold boot
не измерен**. Ready опрашивался с шагом около30 мс; idle — всего2–3 отсчёта
в окне80 мс. RSS повторно считает shared pages; private bytes и сырые локальные
отсчёты сохранены. Это маленький стенд на текущей машине, не требования RAM
будущей программы и не benchmark моделей. WPF также имеет измеренные паузы,
поэтому production responsiveness ещё не принят.

## Доступность и DPI

Qt: реально проверены Tab/Space для примера/расчёта/фоновой задачи и Escape;
UIA видит действия, источник, статус и текст результата. Однако таблица
экспонирует большое дерево, snapshot был усечён на10010 детей, а Value результата
однажды оставался прежним при актуальном document_text. Это ограничение,
не доказанная причина пауз. Эффективные Qt DPR1,25/1,5/2 проверены (последние два —
override поверх системных125%). Кнопки перенесены в сетку; при200% и19px шрифте
экран/viewport тесен. Системные200% этим не подменяются.

WPF: native file picker открыл собственный PDF, клавиатурные действия/отмена,
Ctrl+End, реальный crash/recovery, полный UIA Value результата и source/page
наблюдены. Сортировка/выбор 10000 строк также проверены компонентным прогоном,
реализованных визуальных строк около15. Крупный шрифт19 читабелен при системных125%.
WPF при системных200% **не проверен**. Кнопка системной палитры при HighContrast=false
не является испытанием системного контраста. В Qt проверена собственная контрастная
палитра. Narrator запускался; отправлены команды фокуса/чтения, но слышимое чтение
не наблюдалось, поэтому полный Narrator pass отсутствует. Эти gates остаются открыты.

## Сборка, лицензии и сопровождение

PyInstaller6.22.3 создал Qt onedir: 202 файла,136319176 байт (около130MiB).
Фактически есть Qt6Core/Gui/Widgets/Network/Svg DLL; отсутствие сетевого UI не
убирает лицензии DLL из build inventory. Запуск **неуспешен**: QtCore DLL load
failure. Точные SHA и список файлов — `builds.json`. WPF EXE31744 байта +config341
байт запущен практически, но полагается на системный .NET и внешний Python worker.
Сравнивать32KB с130MiB как размеры полных установщиков нельзя: обе поставки
ещё не включают завершённый private worker/runtime/installer.

PySide6/Shiboken metadata: LGPL-3.0-only OR GPL-2.0-only OR GPL-3.0-only;
проверены фактические колёса и хеши notices. Их dist-info содержит commercial
license reference, что **не заменяет полный комплект LGPL/Qt/third-party notices**.
Core/Gui/Widgets/Network/Svg надо учитывать по конкретной6.11.3 сборке.
Официальные сведения: [Qt for Python](https://doc.qt.io/qtforpython-6.11/licenses.html),
[Widgets](https://doc.qt.io/qt-6.11/qtwidgets-index.html),
[Network](https://doc.qt.io/qt-6.11/qtnetwork-index.html),
[SVG](https://doc.qt.io/qt-6.11/qtsvg-index.html).
Если Qt будет поставляться по LGPL, нужны соответствующие исходники/предложение,
уведомления и возможность замены библиотек; обычный onedir сам по себе этого не
доказывает. [Обязательства Qt](https://www.qt.io/development/open-source-lgpl-obligations).
Платный договор не выбран и не приобретается.

pypdfium2: Apache2.0/BSD3 для binding; PDFium — BSD-style и отдельные лицензии
встроенных компонентов. Колесо содержит BUILD_LICENSES с SHA, их нужно переносить
в будущую поставку. PDFium не thread-safe; здесь вызовы идут в отдельных процессах.
[Лицензирование и ограничения проекта](https://github.com/pypdfium2-team/pypdfium2#licensing).
Pillow13 — MIT-CMU, psutil7.2.2 — BSD3; ReportLab4.4.9 используется только при
авторинге собственного PDF. PyInstaller GPL2+exception не отменяет обязательства
зависимостей. [Лицензия PyInstaller](https://pyinstaller.org/en/stable/license.html).
WPF этого опыта — Microsoft .NET Framework из ОС; его нельзя автоматически
обозвать MIT-redistributable modern .NET. Условия Windows/.NET и private runtime
проверяются для фактической поставки WIN-02. Собственную code-license проекта
пользователю не назначали. Бинарники/колёса/PDF/снимки в Git не включены.

WPF оставляет финансовое ядро в Python, но добавляет небольшой C# frontend и
сборку csc. Для пользователя+Codex это дополнительное сопровождение, которое
сейчас оправдано двумя воспроизводимыми проблемами Qt. Общие IPC/renderer/adapter
уменьшают дублирование. Это не разрешение развивать два полноценных UI.

## Проверки, границы и следующий шаг

12 новых slice tests и3 Qt component tests прошли; отдельно8 записанных фактических
component runs проверены независимым валидатором: каждый дал2 расчёта,5 render
состояний, одну отмену и crash23 с восстановлением.64 rotation×zoom×DPI комбинации
проверены по независимым координатам и зелёным пикселям. Реальные UI действия
описаны отдельно, не выдаются за компонентные тесты или полную приёмку доступности.
Неизменность старых файлов/заморозок доказывается SHA, а не новым прогоном
исторических799unit/18AppTest. Qwen не запускался/не опрашивался/не менялся.

Границы: один собственный PDF, без crop/multipage/scan/OCR/import-any-PDF;
worker — отдельный процесс, не защитная песочница; нет production IPC/job supervisor,
installer/подписи/clean VM/нового финансового benchmark/пользовательской приёмки.
Будущие private worker и runtime не должны зависеть от Value/OneDrive/Git/cwd.

Следующий отдельный этап — **только WIN-02**, private Python/runtime и installer
для WPF на чистой Windows11 x64, плюс честная проверка оставшихся DPI/Narrator
рисков выбранной поставки. Здесь WIN-02 не запускается. Полный промт:
[windows_02_private_runtime_installer_spike.md](../../prompts/windows_02_private_runtime_installer_spike.md).
Доказательства: [evaluation/windows_01_2026-11-11](../../evaluation/windows_01_2026-11-11/).
