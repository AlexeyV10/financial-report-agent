# Агент, поиск, проверка качества и локальные границы доверия

Проверка первичных источников:11.11.2026. Это исследование и проектные выводы, не внедрение библиотек, не новая оценка Qwen и не обещание безопасности. Персональные документы никуда не отправлялись. Текущие пользовательские решения: универсальные финансовые документы, Windows-приложение, сначала только локальный Qwen. Облако в первую реализацию не входит.

## 1. Агент не должен становиться единственным способом работы

Предлагаемая модель продукта: приложение само умеет открыть документ, показать таблицу, выполнить зарегистрированную проверку и построить график. Агент выбирает эти действия и объясняет результат. Отказ модели или нехватка памяти не лишают человека библиотеки, поиска, формы, таблиц, проверок и ранее сохранённых результатов.

У нынешнего проекта уже есть важное преимущество: B/калькулятор/admission/Evidence отделены от решений A/C. При расширении нужно сохранить эту границу и заменить узкий каталог/грамматику версионированными документными и финансовыми адаптерами. Переписывать всё на агентный фреймворк только ради названия продукта не требуется.

| Средство | Проверяемый первичный факт | Решение для этого проекта |
|---|---|---|
| Собственный application-service и ограниченный controller | Уже существуют и проверены в коде проекта; текущие ответы зависят от typed inputs и разрешённых операций | Начальный выбор. Добавить устойчивые jobs/checkpoints/инструменты, сохранив финансовое ядро |
| LangGraph | Документация описывает persistence/checkpoints и durable workflow capabilities [R01] | Кандидат для действительно сложных возобновляемых исследований. Отдельный spike, без обязательного Agent Server/Postgres/облачного LangSmith |
| Pydantic AI | Поддерживает локальный Ollama и несколько схем structured output [R02–R03] | Возможный typed adapter; schema-valid JSON всё равно не доказывает верный показатель/ячейку. Проверять provider defaults и точную версию |
| LlamaIndex | Есть полностью локальный пример с Ollama/локальными embeddings; installation docs отдельно описывают default providers [R04–R05] | Полезные retrieval/ingestion абстракции, но не устанавливать весь ecosystem. Никакого неявного OpenAI/remote embedding fallback |
| Haystack | Pipelines соединяют компоненты, Document Store отделён от Retriever [R06–R07] | Альтернатива для документного pipeline, не дополнительная обязательная платформа поверх всех предыдущих |
| SQLite FTS5 | Встроенный полнотекстовый поиск и BM25 [R08] | Основной transactional store/lexical baseline уже знаком. Проверить русскую нормализацию, единицы и числовые токены |
| DuckDB | Встраиваемая аналитическая БД [R09] | Опционально для больших табличных выборок/CSV, если измерения покажут необходимость. Не второй независимый источник истины для принятых Fact |

Выбор собственного controller сейчас — инженерный вывод по существующей базе, а не доказательство превосходства над LangGraph. Вводить одну внешнюю абстракцию следует под наблюдаемый недостаток: возобновление, retrieval или schema integration, с проверкой миграции и зависимостей. Сразу LangChain+LlamaIndex+Haystack+несколько vector DB увеличат площадь сопровождения без доказанной пользы.

## 2. Как искать по любым документам, сохраняя точные числа

Предлагаемый порядок:

1. Классифицировать запрос: конкретная сумма/таблица, сравнение, обязательство, объяснение, сверка документов, сценарий или прогноз.
2. Ограничить workspace/документы, сторону, стандарт, полный период, версию и тип источника. Явное уточнение имеет приоритет над удобным default.
3. Использовать структурированные поля и SQLite FTS5/BM25. Числовой поиск и точные подписи не заменять только embeddings.
4. Добавить локальный semantic index, если на отдельном русском наборе зафиксированы промахи lexical baseline. Модель embeddings, tokenizer, размерность, chunking, язык и ревизия входят в fingerprint.
5. При необходимости rerank локально. Проверять прирост evidence recall/полноты и цену RAM/времени. Высокий retrieval score не является финансовой уверенностью.
6. Вернуть не свободный текст без координат, а типизированный набор страниц/таблиц/ячеек/примечаний с точной версией и разрешённым происхождением.
7. Доказать комплект входов и правила допуска, затем рассчитать кодом. Частично найденный комплект не разрешает подставить знакомый Fact из другой версии.

Это **проектный pipeline**, не измеренный новый retrieval. Векторная БД, GraphRAG, multimodal retrieval и длинный context не заменяют эти проверки. Граф связей полезен для «договор→счёт→платёж» и «показатель→примечание», но его рёбра также требуют источника. Автоматически добавленная моделью связь остаётся кандидатом.

На длинных PDF нужны иерархия документа, страницы/разделы, таблицы и связи с примечаниями; один гигантский prompt и один плоский Markdown теряют управляемость. Для каждой стадии сохранять режим, время, реальные найденные элементы и причину пропуска. Переиндексация выполняется после изменения соответствующего fingerprint в новом пути, без подмены старого frozen index.

## 3. Контролируемые возможности будущего агента

Предлагаемые инструменты: `list_documents`, `inspect_document`, `find_tables`, `search_evidence`, `get_admitted_facts`, `get_note`, `compare_versions`, `run_metric`, `reconcile_transactions`, `list_obligations`, `build_cash_calendar`, `run_scenario`, `forecast_series`, `prepare_export`. Это имена будущего API, не уже реализованные функции.

Каждый инструмент получает IDs и проверенный typed request. Ни вопрос, ни текст файла не создают путь к произвольному файлу, URL, SQL, Python, shell, subprocess или admission. Точный источник открывает UI broker по document/file ID. Расчёт выбирается из реестра определений; произвольный Python, написанный моделью, не исполняется.

На сложный запрос сначала показывать понятный план: «найду долг и сроки → сверю с примечанием → сопоставлю с деньгами → выделю неизвестное». Статус показывает только действительно выполненные шаги. Несколько частей вопроса дают список fulfilled/unfulfilled; один процент не выдаётся за полный анализ.

Долгие задания сохраняются в SQLite: job/run ID, input identity, контекст источников, версия методики/модели, checkpoint, progress, ошибка, отмена, outputs. Возобновление не повторяет уже исполненное действие с побочным эффектом. Нужны idempotency keys и атомарная публикация результата. Перезапуск UI не превращает архив в новый ответ; смена источника/периода/версии инвалидирует привязку текущего ответа.

Полезная память — подтверждённые настройки пользователя и версии локальных правил. Разговорная догадка модели не превращается в Fact. Исправления пользователя записываются как изменения конкретного поля/сопоставления; выбор компании не считается проверкой всех сумм. Новые шаблоны должны иметь scope, примеры и тесты; «обучение» на исправлении не означает автоматический fine-tuning Qwen на личных документах.

## 4. Четыре уровня доказательности ответа

| Вид вывода | Требуемая опора | Как показывать |
|---|---|---|
| Сообщено в документе | Точная цитата/ячейка и версия | «В отчёте указано…» |
| Рассчитано | Допущенные входы + формула/единицы/округление | «Рассчитано по…» |
| Аналитическая интерпретация | Проверенные наблюдения, правило, ограничения/альтернативы | «Это может указывать на…; для проверки нужно…» |
| Сценарий/прогноз | Явные предпосылки или модель/история/cutoff/backtest | «При этих предположениях…» / «Прогноз модели…» |

Нельзя переводить объяснение руководства в доказанную причинность. Например, найденная фраза о повышении цен — атрибутированное утверждение компании, а не наш установленный причинный эффект. Нельзя называть риск-флаг доказанным мошенничеством или аудиторское мнение гарантией платёжеспособности.

Финальный renderer должен проверять денежные/процентные claims против CalculationReceipt и выбранных Fact. Для текстовых claims нужны собственные проверки атрибуции, охвата и отсутствия неподтверждённых утверждений. Самооценка второго вызова той же LLM не является независимым финансовым oracle.

## 5. Безопасность как часть архитектуры локального приложения

OWASP отмечает indirect prompt injection через внешние файлы и то, что RAG сам по себе проблему не решает. NIST AI RMF — добровольный подход к управлению рисками, а не готовая сертификация нашего продукта. [R10–R11]

Проектные границы:

- PDF/Office/OCR и их вложения — недоверенные данные. Не исполнять JavaScript PDF, VBA, DDE, external workbook connections, embedded executable или инструкции из ячеек.
- Импорт отделён от анализа. MIME/signature/размер/страницы/декомпрессия/число файлов проверяются до тяжёлого разбора; ZIP-slip/ZIP-bomb/симлинки и неразрешённые вложения отклоняются. Пароль защищённого файла вводит пользователь, он не попадает в prompt/log.
- Parser/OCR workers получают минимум файловых прав, отдельный temp и лимиты времени/памяти/выхода; сеть им не нужна. Job Object завершает дерево и ограничивает ресурсы, но сам по себе не является sandbox. AppContainer/restricted token требуют собственного proof совместимости [R12].
- LocalOnlyPolicy разрешает inference только выбранному локальному backend. Конфиг cloud provider, переменная окружения с API key или имя `-cloud` не должны неявно включать отправку документов. Скачивание signed model pack — отдельное явное действие, не загрузка документа в облако.
- Вопрос/документ не меняют tool registry, security settings, definitions, publication evidence, права, хеши и происхождение Fact. Внешние ссылки открываются только после явного действия, не автоматически из model prose.
- Секреты/ключи — в предназначенном Windows хранилище, документы/БД — отдельно от install directory. SQLite не шифруется автоматически. DPAPI защищает данные/ключи в своём пользовательском контексте; portable backup нуждается в отдельной схеме восстановления [R13].
- Собственная выгрузка не включает первичные страницы/полный текст по умолчанию; CSV/Excel formula injection предотвращается. Диагностика имеет preview/redaction; автоматических upload/crash telemetry с личными документами нет.
- Обновления приложения/моделей принимаются по подписанному каталогу и SHA; каталоги/пути не берутся из документа. Ресурс нельзя заменить только потому, что новое имя похоже на старое.

Эти пункты — план реализации и тестирования. Старые143 known probes не являются испытанием новой PDF sandbox или всего будущего агента;20 controller mocks нельзя считать actual model attacks.

## 6. Как проверять реальную пользу

| Уровень | Отдельная проверка |
|---|---|
| Импорт/распознавание | file acceptance, OCR CER/WER, таблица/reading order, exact-cell raw/sign/scale/period/locator accuracy, runtime/RAM |
| Семантика/допуск | Правильность entity/standard/definition/version; false admission и корректное abstention/clarification |
| Retrieval | Полный комплект evidence recall, MRR/nDCG где уместно, ошибки по типу документа и языку |
| Расчёты | Независимые целые дроби/Decimal/oracles, нулевые/отрицательные/неполные/несопоставимые входы |
| Агент | Достижение задачи, лишние вызовы/ошибки/лимиты/неисполненные части, claims groundedness и полнота раздельно |
| Прогноз | Rolling-origin, naive baseline, MAE/MASE при определимости, bias, интервальная coverage/width, horizon-specific ошибки |
| Desktop | Clean-VM install/update/rollback, offline, no-console, отмена/восстановление, UIA/Narrator/DPI, работоспособность на заявленном hardware |
| Удобство | Реальные пользовательские задачи и наблюдённая успешность; отсутствие интервью/пилота не заменяется тестами Codex |

FinanceBench исследует open-book financial QA; FinQA — многошаговое числовое рассуждение; TAT-QA — объединение текста и таблиц; OmniDocBench — разбор документов. Это разные задачи, и оценка одного слоя не подтверждает остальные. Их публичность также не делает их unseen для pretrained модели. Лицензии code/dataset/source PDF проверяются отдельно. [R14–R17]

Нужен свой rights-cleared русский корпус разных типов и макетов. Предварительный ориентир для планирования: десятки разнообразных документов и сотни вручную заданных проверок с отдельными release slices; точные объёмы фиксировать до эксперимента после изучения доступных источников. Дубликаты comparative, одинаковые шаблоны и переформулировки не увеличивают независимую выборку. Разделять эмитентов, bank/export templates, document families и временные версии; locked holdout не использовать для настройки.

На текущих48Fact/8PDF/2lineages нельзя честно объявить новую универсальную точность или готовность прогнозов. При смене engine/prompt/model/extractor создаётся новая серия. Старые frozen14/138raw16 и результаты сохраняются; прежние799unit/18Streamlit AppTest не становятся тестами нового Qt/WPF приложения.
