# WIN-05 · Общий сервис и типизированный обмен

Команда `own_margin` открывает один разрешённый учебный источник, считает
операционную маржу и возвращает источник результата. CLI и новое пробное окно WPF
обращаются к одному `ApplicationService`. Окно вызывает фиксированный CLI из
каталога установки. CLI запускает фиксированный частный Python и передаёт ему
один запрос. Для запуска `--install-root`, `--app-data` и `--vault` передаёт
доверенный вызывающий код. Сообщение для worker содержит только логический ID
ресурса. [Сервис](../../src/financial_assistant/application_service.py),
[CLI](../../spikes/windows_05/service_cli.py), [окно WPF](../../spikes/windows_05/TypedHost.cs).

Запрос версии `win05-request-1` содержит `run_id`, `context_id`, `command` и
`arguments`. `context_id` связывает выбранный vault, его реестр ресурсов, версию
операции и контрольные суммы установленных метаданных примера. При изменении
реестра, переносе vault или выборе другого vault ранее полученный ID не годится
для запуска. Ответ `win05-response-1` повторяет идентификаторы запроса.
Успешный ответ содержит число, страницу, рамку и SHA-256 источника. В техническом
отказе результат пуст, а причина передаётся одним стабильным кодом.

Передаётся одна UTF-8 строка JSON, завершённая LF. Запрос ограничен 8192 байтами,
ответ и stderr отдельно ограничены 65536 байтами. Проверяются закрытые поля, типы,
повторяющиеся ключи, неполное и лишнее сообщение и совпадение идентификаторов.
Клиент ждёт EOF и нулевой код процесса. Отказ или ненулевой код не разрешают
сохранить финансовый результат. Лимит ожидания worker составляет 10 секунд,
лимит ожидания CLI из окна — 15 секунд. [Транспорт](../../src/financial_assistant/typed_ipc.py).

Квитанция публикуется один раз после принятого ответа. Сервис повторно сверяет
хранилище, регистрацию и SHA источника. Повтор ID в одном vault получает
`duplicate_run`, прежний результат остаётся по прежнему пути. Запуски в разных
vault независимы. Управление повторным вычислением, длительной очередью и всем
деревом процессов относится к следующему этапу.

## Проверка на Windows

В отдельной пробной установке с CPython 3.14.10 CLI и обработчик кнопки
отрисованного окна WPF получили `15.00` в двух разных vault. Совпали операция,
контрольная сумма, страница 1 и рамка `[300, 186, 340, 210]`. Квитанция окна в режиме
проверки сформирована собственной диагностикой WPF после `ContentRendered` и
вызова обработчика обычной кнопки. Устаревший ID первого vault отвергнут во втором.
В нативном окне отсутствие PDF дало `source_missing` и пустой результат.

Двенадцать тестов транспорта прошли как на MSYS2 3.14.7, так и на stock
CPython 3.14.10. В том числе проверены настоящий дочерний процесс, превышение
каждого лимита вывода, неполный и лишний кадры, неверная корреляция, неверный UTF-8,
тайм-аут и ненулевой код после сообщения об успехе. Прежний сквозной сценарий
WIN-04 пройден повторно. [Квитанция](../../evaluation/windows_05_2026-11-19/service.json).

```powershell
python -X utf8 -I -B spikes/windows_05/check_service.py --runtime-build tmp/runtime-a --demo tmp/own-demo --out tmp/service-e2e
python -X utf8 -I -B -m unittest discover -s spikes/windows_05 -p test_typed_ipc.py -v
```

Для повтора нужны входы [WIN-03](stock_runtime.md) и штатный .NET Framework x64 с
WPF. Проба запускает краткое окно на рабочем столе испытания. Гостевой установщик
WIN-02 остаётся отдельно от этой пробной поставки. В тесте использовался
вымышленный PDF. [Следующий этап WIN-06](../../prompts/windows_06_supervisor.md).
