# WIN-07 · SQLite-хранилище рабочего проекта

У выбранного vault свой файл `vault.sqlite3`. SQLite проверяет идентификатор
приложения, версию схемы и принадлежность базы логическому ID хранилища. Первое
пополнение пустой базы создаёт схему версии 1 транзакционно. Несовместимая версия
или чужой ID приводят к отказу. [Модуль хранения](../../src/financial_assistant/vault_storage.py).

Оригинал хранится как байты с размером и SHA-256. Версия документа ссылается на
один оригинал. Новая обработка создаёт отдельную производную ревизию. Реестр
версий, обработанный текст и запись FTS5 попадают в одну транзакцию. Совпадающий
импорт возвращает прежние номера. Поиск получает обычную фразу и возвращает
номера совпавших ревизий. SQLite выполняет фиксированные запросы с параметрами.

Резервная копия создаётся штатным SQLite Backup API в отдельный новый файл.
До публикации проверяются схема, принадлежность vault, контрольные суммы
оригиналов, связи и согласованность индекса. Восстановление открывает копию на
чтение и публикует проверенную базу только в выбранном отдельном каталоге с тем
же логическим ID. Старые квитанции и журнал заданий остаются в своих каталогах.
[Реализация копирования](../../src/financial_assistant/vault_backup.py),
[SQLite Backup API](https://www.sqlite.org/backup.html).

## Испытание

```powershell
python -X utf8 -I -B -m unittest discover -s spikes/windows_07 -p test_vault_storage.py -v
python -X utf8 -I -B spikes/windows_07/check_storage.py --runtime-build tmp/runtime-a --demo tmp/own-demo --out tmp/storage-e2e
```

Штатный CLI принимает явные корни установки, приложения и vault. Встроенный
импорт работает с собственным PDF, проверяет его SHA и возвращает `15.00` с
первой страницы. Просмотр сохранённых байтов не требует повторного открытия
файла, из которого они были импортированы. Сценарий добавляет второй текстовый
вариант в одну базу, проверяет русскоязычный поиск и восстановление отдельно от
второго vault. Прогон выполняется через закреплённый Windows Python.
[CLI](../../spikes/windows_07/vault_cli.py), [квитанция](../../evaluation/windows_07_2026-11-19/storage.json).

Проверка резкого завершения процесса остановила реальный импорт при вызове
COMMIT. Повторное открытие подтвердило прежние байты и отсутствие незавершённых
оригинала, ревизии и индекса. Отдельная проверка `SQLITE_FULL` достигла лимита
страниц в пробной базе. Это контролируемый тест ошибки SQLite. [SQLite PRAGMA](https://www.sqlite.org/pragma.html#pragma_max_page_count).

На обоих Python пройдены по 10 тестов, включая несовместимую схему, два vault,
неизменяемые оригиналы, несовпадающий текст FTS, переполнение и восстановление
проверенной копии с отказом перезаписи. В сквозном прогоне совпали SHA и размер
копии и восстановленного файла. Свежий снимок занимал 73 728 байт.

Учебная поставка использует ограниченный локальный импорт. Подключение базы к
основной оболочке и расширение просмотра идут в WIN-08 и WIN-09. [Сценарий WIN-08](../../prompts/windows_08_native_shell.md).
