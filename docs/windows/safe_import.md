# WIN-11 · Безопасный приём файла

На экране «Документы» можно выбрать локальный файл через стандартный
диалог Windows. Работник проверяет фактические байты и сохраняет принятый
оригинал в выбранном хранилище с SHA-256. Расширение имени служит
подсказкой для пользователя. Тип определяется по содержимому. Одинаковые
байты внутри одного проекта дают один оригинал. Другой проект хранит свою
запись отдельно.

После сохранения интерфейс отдельно показывает, что файл принят,
извлечение ожидается и факты ещё не проверены. До следующей стадии документ
не попадает в FTS и не участвует в расчётах. При отказе экран показывает
причину, а поля хеша и размера очищаются. Отмена диалога не начинает
импорт.

Распознаются PDF, XLSX, DOCX, PNG, JPEG, TIFF, CSV и UTF-8 или UTF-16
с маркером для текста. Максимальный размер входного файла 16 МиБ.
Для PDF проверяются до 100 страниц размером до 8192 пунктов по каждой
стороне. Зашифрованный PDF отклоняется. PDFium открывает документ для
чтения размеров страниц. Действия, формы и вложения не запускаются.
Для изображений действуют ограничения по ширине, высоте, числу кадров
и пикселям.

ZIP читается в памяти. Проверяются имена и типы записей, CRC, число
элементов, глубина пути, размеры, коэффициент распаковки и структура
пакета Office. Архивы с недопустимыми путями, ссылками, шифрованием,
активными вложениями, внешними связями или XML с объявлениями сущностей
получают отказ. Содержимое не распаковывается в файловую систему.
Обычный ZIP не считается документом. На этом этапе структурная проверка
не проверяет финансовый смысл текста, формул и таблиц.

Запись первого принятого файла переводит прежнюю базу с версии 1 на
версию 2. Переход и сохранение байтов происходят в одной транзакции.
Файлы, которые уже участвовали в анализе, и старые правила поиска
проверяются при открытии обеих версий. Снимок и восстановление работают
с обеими схемами.

Сквозной прогон вызвал тот же обработчик, который получает выбранный
в диалоге путь. CSV с расширением `.txt` принят по содержимому. Повтор
вернул тот же SHA-256. Два одновременных запуска во втором проекте дали
один принятый файл и один дубликат. Точное содержимое сверено в каждой
базе. В каждом FTS осталось ноль строк. Отказ для пути, выходящего из
архива, произошёл ещё до создания базы.

Пройдены 13 тестов форматов, по 9 проверок приёма и по 10 проверок старого
хранилища на двух версиях Python. Воспроизведено переполнение SQLite.
Транзакция сохранила прежние данные и схему. Все пять расчётов D0 вместе
с просмотром прежнего источника прошли регрессию. Сквозная проба проверяла
обработчик после выбора файла. Отдельный прогон системного диалога остаётся
в общей приёмке интерфейса.
