# Создание чистой Windows для WIN-02B

19.11.2026. **Машина готова к испытанию установщика.** VirtualBox загрузил
`ProjectPractice-WIN02B-W11` с её виртуального диска и с отключённым сетевым
кабелем. Снимок `Before-WIN02B-2026-11-19` сделан на выключенной машине, до
подключения проверочного диска. В Проводнике гостя этот диск виден как
`D: WIN02B_KIT`. Он содержит прежний установщик и сборщик без изменений.

Пользователь создал `WIN02B-Test` и сообщил о входе. Запущенный в госте
`START-PREFLIGHT` подтвердил, что текущий пользователь не состоит в группе
администраторов. Сборщик прочитал Windows 11 Enterprise Evaluation, сборку 26300,
и .NET Framework с Release 533509. При первоначальной проверке настроек Windows
наблюдались версия 26H2 и полная сборка 26300.9457. На рабочем столе 19 ноября
указано 82 дня действия пробной лицензии. Отдельная страница активации не проверялась.

Ethernet имел состояние Down. Сборщик не нашёл известных записей Python или Ollama
в предусмотренных местах поиска, подтвердил хеш установщика, увидел исходное
состояние без приложения и вернул пустой список препятствий. Часы гостя отдельно
не сверялись с хостом. Полный результат хранится в госте, а в репозиторий входят
[поля проверки без частных данных](../../evaluation/windows_vm_install_2026-11-11/preflight-observed-2026-11-19.json).

Первый запрос управления окном истёк. После подключения была видна гостевая
система, но клики не открывали Проводник. Навигация и запуск собственного ярлыка
удались через штатную передачу клавиш конкретной машине в VirtualBox.

Следующий этап — интерактивная установка, проверка расчёта и удаления в госте.
Сценарий подготовлен в [промте продолжения](../../prompts/windows_02b_execute_guest_acceptance.md).
Статус WIN-02 пока `host_validated_clean_vm_pending`.

## Как была создана машина 11 ноября

Пользователь явно поручил установить VirtualBox и создать Windows для испытаний.
Первую установку VirtualBox пользователь завершил самостоятельно после того,
как автоматические попытки запуска не показали ему запрос администратора.
Проверены установленная версия **7.2.22r175245** и действительная подпись Oracle.
Выбранные пользователем компоненты installer не наблюдались; их нельзя выдавать
за выполненную ассистентом минимальную установку.

Ассистент создал одну новую зарегистрированную машину **ProjectPractice-WIN02B-W11**
в локальном каталоге машин VirtualBox, вне OneDrive и Git.
Установка Windows запущена на её собственный новый динамический VDI. В мастере
фактически наблюдались единственный `Disk 0 Unallocated Space 64.0 GB`, редакция
Windows 11 Enterprise Evaluation, выбранная чистая установка, копирование файлов
и последующая загрузка этапа настройки с виртуального диска.

**Текущую степень готовности** следует брать из `report.json` и финальной
локальной квитанции этапа, а не из наличия файлов машины. До завершения OOBE,
проверки учётной записи и чистого снимка готовность к приёмке не заявляется.
WIN-02 остаётся `host_validated_clean_vm_pending`; приложение WIN-02 в госте
на этом этапе не устанавливается и не принимается автоматически.

## Фактические настройки машины

| Параметр | Значение |
|---|---|
| Гостевая платформа | Windows 11 x64, новый VDI, официальный ISO Enterprise Evaluation26H2 en-US |
| RAM | 4096 МиБ |
| CPU | 4 виртуальных процессора после исправления зависания с2 |
| Виртуальный диск | 65536 МиБ, VDI Standard dynamic, SATA/IntelAhci |
| Прошивка | EFI, Secure Boot включён, TPM2.0 |
| Экран | VBoxSVGA,128МиБ,3D выключен |
| Аудио | Выход включён, вход выключен |
| Сеть | NAT для первоначальной настройки; host bridge/port forwarding не настраивались |
| Общие папки/буфер/drag-and-drop | Не добавлялись/выключены |

Это параметры конкретной учебной машины без модели. Они не являются измеренными
минимальными требованиями полного приложения с Qwen. Hyper-V хоста оставался
активным; VirtualBox использовал NEM/Windows Hypervisor Platform. BIOS, защита,
загрузочная конфигурация и системные компоненты хоста ассистентом не менялись.
Перезагрузки установки относятся к гостю; перезагрузка хоста не выполнялась.

## Первые ошибки и исправления

1. Запуск собственного проверенного VirtualBox installer через Computer Use
   завершился timeout. Другой обычный запуск с запросом повышения завершился
   сообщением Windows «операция отменена». Пользователь сообщил, что запрос не
   появился. Это не доказательство того, что он сам нажал отмену.
2. После самостоятельной установки менеджер и VBoxSVC работали с повышенными
   правами; это проверено чтением TokenElevation. Ввод обычного процесса
   ассистента не управлял их окнами. Пользователь закрыл менеджер; он был заново
   запущен обычным способом. Никакие защитные барьеры не отключались.
3. Новая VM с2vCPU зависала до Windows Setup, с чёрным экраном и остановившимся
   EFI-журналом около `PciHostBridgeDxe`. После изменения только CPU с2на4 EFI
   прошёл до загрузчика DVD. Наблюдение согласуется с
   [обсуждением issue799 в официальном репозитории VirtualBox](https://github.com/VirtualBox/virtualbox/issues/799),
   но не доказывает полную причину и не является повторным benchmark.
4. Первая попытка изменить CPU сразу после poweroff получила ещё удерживаемую
   блокировку сессии. После завершения выключения команда прошла; блокировка
   принудительно не удалялась. В этот момент VDI был пустым,2097152байта.
5. Приглашение DVD загрузки сначала пропускалось. Для него использован штатный
   документированный `VBoxManage controlvm keyboardputscancode`, передающий Enter
   в прошивку только нашей VM. Затем Windows Setup действительно открылся.
   Ввод в гостевой мастер также передавался этим API; окна хоста наблюдались
   через Computer Use. Обычный UI-ввод в окно VirtualBox не продвигал гостя.
6. Попытки получить CLI-подсказку через `--help` показали usage/error без изменения
   VM; актуальная справка получена через `VBoxManage help`. Ранние ошибки сохранены
   отдельно от последующего фактического результата.

Полные VM-журналы, конфигурация с machine IDs/MAC, captures и частные checkpoints
остаются только в исключённой `tmp/` либо в локальной папке VM, не в Git.

## Границы и следующий шаг

Microsoft предоставляет90-дневную Evaluation по опубликованным
[условиям и инструкциям](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise).
Не выдумывать регистрационные сведения, не обходить вход/активацию/TPM/Secure Boot
и не продлевать trial. Вход, пароли, создание учётной записи и выбор параметров
конфиденциальности выполняет пользователь в самом госте. Чат для паролей не нужен.
Редакция/период Evaluation и источник ISO не заменяют фактическую проверку
активации/версии готовой гостевой ОС.

После готовности среды использовать существующий
[сценарий WIN-02B](../../spikes/windows_02b/RUNBOOK_RU.md). Перед испытанием нужна
обычная гостевая учётная запись без Administrators, подтверждённые OS/build/.NET,
происхождение чистой установки, снимок до приложения и отключённая сеть только
гостя для offline-проверки. Отправленная команда/конфигурация не равны наблюдённому
UI или слышимому Narrator. WIN-03/04/54 и академические18/19/20 не запускались.

Существующий Qwen не запускался, не опрашивался и не менялся. Ядро, формулы,
frozen gold, RC pins, старый UI/venv и КП1 не изменяются этим этапом.
