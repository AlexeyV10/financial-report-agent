Источник создан с нуля и подписан как вымышленный, не скопирован из отчёта эмитента. Фиктивные PDF/page-поля — только совместимость старой схемы, не утверждение о PDF. Бюджет доли округляется вниз до копейки, лоты вниз, платежи HALF_UP до копейки. Комиссия сверх лимита номинала требует отдельного cash; при нехватке — остановка, не скрытое уменьшение количества. Проскальзывание уже в цене и не вычитается повторно.

Выбраны pdfplumber 0.11.9 в уже доступном комплектном Python 3.12.14 и SQLite FTS5 основного Python 3.14.7. Это не установка нового тяжёлого стека. Геометрическое разделение разворотов задано для выбранного документа и проверено на целевой странице. Ручной фрагмент оставлен явным резервом; сбой парсера не переключает режим молча.

BM25 отдавал приоритет определению показателя; добавлен общий приоритет строк с числами, начинающихся со слова запроса, без использования эталонной страницы/значения. Нужная страница остаётся второй в пяти результатах, что явно отражено в отчёте. Это небольшая публичная проверка, не измерение преимущества над другими методами. Выход поиска — candidate-конверт, не новое подтверждение Fact. Подробности и ограничения: docs/retrieval.md.

Первое примечание не выбирается по рангу автоматически: нужны оба Evidence с точными метаданными; candidate.text не становится числовым входом. ## Шаг 8: единый CLI и валидированный текст

09.11.2026 выбран один CLI-вход без новых зависимостей: явно ограниченный сценарий вместо заявления о произвольном NLP. Пользователь задаёт понятные поля, ID разрешаются из существующего реестра. Понятный CLI даёт минимальный проверяемый результат; веб-форма оставлена возможным расширением. См. docs/user_path.md.
