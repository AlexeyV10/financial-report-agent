# Шаг 6: локальное извлечение и поиск

09.11.2026. Протокол завершения шага 6: тогда было 68 тестов; текущие 98 после шага 7 описаны в docs/finance.md. Реализованы получение текста из выбранного PDF и поиск по локальному индексу. Это поиск фрагментов, не агент, LLM, автоматическое подтверждение фактов или завершённый пользовательский ответ.

## Выбранный способ

| Вариант | Проверка и решение |
|---|---|
| Только ручной фрагмент | Самый простой резерв, но не проверяет извлечение из PDF. Сохранён как явно выбранный `--manual`; не включается автоматически при сбое |
| pypdf с layout | Доступен в комплектном runtime. Поддерживает текст/layout, но сам по себе не решает разделение таблиц разворота. В проекте не реализован и не заявляется протестированным парсером |
| pdfplumber с crop | Выбран: уже доступен без установки, позволяет отделить геометрические половины разворота. Автоматически извлечены 23 страницы / 46 непустых половин |
| SQLite FTS5 | Доступен в основном Python без пакетов; пригоден для одного документа и точных фильтров. Векторный поиск и сервер сейчас не нужны |

Основания: [официальный README pdfplumber](https://github.com/jsvine/pdfplumber#extracting-text) описывает crop/extract_text; [документация pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html) — layout и ограничения извлечения; [SQLite FTS5](https://www.sqlite.org/fts5.html) — Unicode61 и BM25. Эти возможности не гарантируют точность таблиц, поэтому проверен конкретный результат.

**Фактически использованы две среды:** основной CPython 3.14.7 / SQLite 3.53.4 для поиска и тестов; комплектный CPython 3.12.14 с pdfplumber 0.11.9 / pdfminer.six 20251230 для извлечения. Ничего не устанавливалось. В основном Python PDF-пакетов нет. `requirements-pdf.txt` фиксирует проверенные версии дополнительного worker; весь набор Python-пакетов/платформ не заявлен побайтно зафиксированным. Другой пользователь может указать свой Python с этими пакетами; такой запуск здесь ещё не проверен.

## Команды

Из корня рабочей папки в PowerShell, если индекс ещё не создан:

```powershell
python scripts\search_documents.py index --pdf-python "C:\Users\Value\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
```

```powershell
python scripts\search_documents.py search --query "выручка 2024 2023" --period 2024 --top-k 5 --output tmp\retrieval\real-result.json
```

Индекс — `tmp/retrieval/document.sqlite`, полный экспорт worker — `tmp/retrieval/document.sqlite.extraction.json`. Если индекс уже есть, повторно выполнять только поиск. Для новой версии указать новый путь `--db tmp/retrieval/another.sqlite` и при индексации, и при поиске. Перезапись существующего индекса запрещена. Прежние архивы шагов 2–5 не содержат модуль шага 6; текущая реализация находится в рабочей папке.

Ручной резерв при доступном исходном PDF, если worker отсутствует или извлечение не проходит проверки:

```powershell
python scripts\search_documents.py index --manual --db tmp\retrieval\manual.sqlite
```

Это поиск **только по минимальному ранее размеченному фрагменту**, а не по всем страницам. В результате будет `extraction_mode=manual_reference_v1`. Отсутствие PDF даже в этом режиме — техническая ошибка: версия исходника должна быть проверяема. Существующий эталонный расчёт из JSON по-прежнему можно проверить без PDF отдельным `check_stage1.py`.

Проверки:

```powershell
python scripts\check_step6.py
```

```powershell
python -m unittest discover -s tests -v
```

Первой команде нужны исходный PDF и уже построенный автоматический индекс. Свежие результаты без текста источника — `evaluation/step6_2026-11-09/report.json` и `unit-tests.txt`. Вторая команда использует синтетические текстовые/файловые подстановки для поиска и не требует пакетов PDF. Она не выдаёт искусственные тестовые байты за настоящий PDF.

## Что извлечено и сверено

Worker проверяет предел 10 МБ / 100 страниц и делит каждую страницу на левую/правую половины по геометрии. Это заранее выбранная конфигурация для конкретного развёрстанного отчёта, не автоматическое распознавание любых макетов. Текст/координаты получены кодом, финансовые значения в worker не вписаны из эталона. Полные половины сохраняются без разбиения посреди таблицы.

PDF SHA-256 совпал с реестром: `824f100d14396c26faacf80a03cca6b20d458c9b5d835201bc80068decb3d6e1`. Перед индексацией и каждым поиском проверяется локальный исходник. Индекс связан с полной записью Document; изменение метаданных версии требует нового снимка.

Ассистент сопоставил извлечённый текст `tmp/pdfs/extraction-probe-left.txt` с существующим рендером `tmp/pdfs/phosagro-recheck-page-4.png`: группа, заголовок таблицы, единица «Млн руб.», порядок 2024 → 2023 и строка с двумя суммами сохранены. Это левая половина PDF 4 / печатная 320. Баланс справа не попал в этот фрагмент. Машинная проверка дополнительно сверяет заголовок/масштаб/колонки и исходные строки с **прежней ручной разметкой**; это регрессионная защита выбранного примера, не независимое подтверждение всего PDF.

Суммы, знак, валюту, интервал, группу и стандарт по-прежнему определяет прежняя ручная сверка и `Fact` v0.1. Индекс не присваивает им новые статусы. В тексте некоторых половин встречается шум от повёрнутых боковых надписей; он не удалялся под видом исправления источника. Сканы/OCR и другие компании/макеты не проверялись. Предел файла не гарантирует защиту от любого сложного/вредоносного PDF; корпус ограничен выбранным документом.

## Выдача и совместимость с Evidence

Выдача `retrieval_schema_version=0.1` имеет `status`, `reason_code`, `extraction_mode`, `warnings`, `results`; при совпадениях — название ранжирования. Каждый результат содержит:

- `fragment_id=document_sha256:pdf_page:page_region`, document/entity/version/hash;
- PDF-страницу с единицы, регион, bbox в PDF points с началом сверху, печатный номер при наличии прежнего ручного локатора;
- полный текст выбранной половины и URL с `#page=N`;
- `verification_status=candidate`, `existing_manual_evidence_ids` — ссылки на **ранее** проверенные Evidence с совпадающим локатором.

Это отдельный поисковый конверт, не подмена строгого Evidence v0.1. Для многих фрагментов пока нет строки, колонки и подтверждённого смысла, поэтому эти поля не выдумываются. Ссылки на прежние Evidence не означают, что новый кандидат автоматически подтверждён. Будущий финансовый модуль должен явно получить соответствующие прежние факты и проверить пригодность; произвольный результат поиска нельзя подставить в калькулятор как `assistant_checked`.

Фильтр `--entity` — точный внутренний ID, `--version` — точный version_id. `--period` принимает год только из размеченной области 2023/2024 и дополнительно требует его в тексте. Это не доказательство одинаковой длительности периодов и не поддержка любого финансового периода. Год утверждения 2025 на странице не разрешает ответ за 2025. Для другой области нужны разметка и обновлённая спецификация; дата подписи не подставляется в период.

Запрос — ключевые слова, не разбор произвольного русского вопроса языковой моделью. Нормализация: Unicode NFKC, регистр, ё → е, явно перечисленные формы выручка/выручки/выручку. Русской морфологии в общем случае нет. Все токены соединяются AND; выражения FTS и SQL из запроса не исполняются, параметризованный SQL получает построенные кодом термы. top_k — 1…10.

## Результаты и ошибки

Первоначальный BM25 предпочёл определение выручки. Добавлен общий приоритет строки, начинающейся с первого содержательного слова запроса и содержащей цифры; внутри групп остаётся BM25. Ранжирование не использует номер эталонной страницы или сами значения. На реальном запросе нужный фрагмент PDF 4 — **второй** среди пяти; первым идёт примечание на странице 11. Это допустимая выдача для последующей проверки, не автоматический выбор единственного верного факта.

Пять публичных smoke-случаев прошли: реальный запрос и вариант «ВЫРУЧКИ» находят нужную половину, другая группа не даёт совпадений, 2025 выходит за размеченную область, исторический запрос даёт `missing/publication_unknown`. Результаты и ранги сохранены в отчёте; это не Hit@5/Recall@5 на закрытом наборе и не метрики агента.

**68 unit-тестов = 41 прежний + 27 новых.** Новые проверяют фильтры, нормализацию, top_k, пустой запрос, отсутствие слова, SQL/FTS-подобный ввод, пропажу/изменение PDF, отсутствие/повреждение/версию индекса, дубли, потерю заголовков/строки/единицы, перестановку годов и чисел, неизвестную публикацию и синтетическую временную границу. Ошибка незакрытого SQLite-соединения на Windows обнаружена и исправлена через явное закрытие; повторный прогон прошёл.

`not_found` означает отсутствие совпадения при заданных фильтрах/ключах, **не отсутствие показателя в отчёте**. `missing/publication_unknown` — отказ исторического доступа. `error` и exit code 2 — технический сбой (`source_missing`, `source_version_mismatch`, `index_missing`, `index_version_mismatch`, `index_invalid`, `extractor_failed`, неверный ввод/путь). Неисправный парсер не включает ручной режим молча.

PDF, полный текст, индекс и поисковые JSON с цитатами остаются в исключённой `tmp/`; CLI запрещает для них выходной путь вне этой папки. Публикация версии и права остаются неизвестными; исторический доступ не разрешается даже после успешного поиска. Проверка строки с вредоносной инструкцией показывает только отсутствие её исполнения детерминированным кодом, а не защиту ещё не существующего агента.
