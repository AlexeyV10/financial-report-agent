# WIN-03 · Закреплённая среда CPython для финансового ассистента

Продолжай Windows-план «Проектной практики» в репозитории `financial-report-agent`.
Прочитай AGENTS.md, рабочие разделы PROJECT_PRACTICE_HANDOFF.md, STATUS.md и
docs/github_collaboration.md. Ветвись от фактической проверенной ветки
`codex/windows-02b-guest-acceptance` в отдельную рабочую копию. Прочитай запись
WIN-03 в docs/windows/roadmap.json и протокол docs/windows/guest_acceptance_result.md.

1. Сверь актуальные официальные версии и доступные Windows x64 артефакты CPython,
   Pillow и PDFium, включая ABI, хеши источников и лицензии. Кандидат на момент
   подготовки сценария — CPython 3.14.9 embeddable x64 в той же ветке, что прежний
   эталон MSYS2 3.14.7. Подтверди его по python.org. Существующий 3.12.10 используй
   как контрольную среду отдельно от будущей поставки.
2. Закрепи SHA-256 входных архивов и версий, описание доставки DLL и модулей.
   Извлекай runtime локально в `tmp/`, проверяй относительные пути архива и
   двукратное независимое развёртывание. Сохраняй бинарники и архивы локально.
   Повтори реальный probe для версий, путей и флагов изоляции.
3. На одинаковой исходной копии сравни полный `unittest discover -s tests` для
   рабочего MSYS2 и выбранного stock CPython, учитывая Python `-I`, UTF-8, stdout
   subprocess и собственный `tmp/`. Зафиксируй число тестов, known failures и
   точную причину. Отдельно обозначь судьбу прежних Streamlit AppTest, проверяющих
   другую оболочку. Никогда не замени ими новый WPF пакет.
4. Прогони существующий `runtime_probe.py` и PDF-пример через частный runtime.
   Сверь неизменный SHA примера, четыре поворота и `15.00`. Изучи SQLite, FTS5,
   OpenSSL, CRT и PDFium DLL. Для WIN-04 сохрани факт прежних 25 ошибок cross-root
   с guard `private_path_required`. Используй штатный корень для проверки WIN-03.
   Изменение контракта путей относится к WIN-04. Существующие WIN-02 и RC pins
   не перезаписывай. Qwen не запускай.
5. Сохрани результаты, технические ограничения и состояние следующего этапа.
   Сверь текущую main, состав изменений и применимые проверки. Опубликуй работу
   отдельным PR. Один проверенный этап не заменяет остальные пункты плана.

Для дальнейших этапов следуй `depends_on` в roadmap. По текущему указанию
пользователя переходи к следующему готовому этапу без ручного запуска промта.
