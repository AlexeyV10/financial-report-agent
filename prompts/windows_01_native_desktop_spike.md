## Результат WIN-01

Проверить основной кандидат **PySide6 + Qt Widgets** и сильную альтернативу **WPF/.NET + Python worker** на одинаковом узком vertical slice. Это timeboxed feasibility/ADR, а не два полноценных приложения. Сначала короткая инвентаризация уже доступных SDK/runtime. Новые зависимости устанавливать только изолированно в tmp/собственное окружение, с версиями/хешами/лицензиями; не менять глобальный Python/пакеты/старый venv/UI. Sandbox/network/install failures требуют реальной эскалации, не обхода. Если кандидат невозможно честно запустить, записать блокер и ограничение сравнения, не называть документальное сравнение практическим испытанием.

Slice каждого практически проверяемого кандидата:

1. Native окно в утверждённом светлом бело-зелёном направлении, понятные русские подписи и file-open; без Streamlit/WebView UI/HTTP UI server.
2. Собственный небольшой PDF с известными строками/единицами/периодом; право распространения своё. Сохранить код генерации/версию/хеш и независимые expected. Не копировать первичный чужой PDF в Git/installer. Перед PDF прочитать pdf skill.
3. Native таблица10000строк с model/view, сортировкой и выбором; не генерировать10000виджетов. Не считать строки новыми финансовыми фактами.
4. Одна прежняя зарегистрированная операция07 через узкий общий адаптер и корректную admission/evidence на собственном demo-каталоге. Финансовую логику в GUI/C# не дублировать. Если неизменный07 не допускает корректный demo без broader path migration, сохранить этот технический блокер; не ослаблять guards для красивого ответа и не выдавать mock за07.
5. Источник/страница и точный highlight, rotation/zoom/200%DPI. Renderer сменный; используемые Qt PDF/PDFium/прочие модули проверить по конкретной версии/лицензии. Viewer не означает автоматически финансовую сверку.
6. Background job progress/cancel, UI не зависает; crash/late response не отображается успешным текущим ответом. Вопросы/документы — данные, никаких eval/exec/произвольных путей/URL/SQL.
7. Keyboard-only/Narrator/UIA/high contrast/125–200%DPI, длинные русские подписи и большой масштаб. У результата есть текст/таблица, не только изображение.

Модель не нужна ради этого slice. Существующий Qwen не запускать/перенастраивать, генерацию автоматически не делать; если понадобится отдельный доказательный model probe, сначала обосновать необходимость в границах WIN-01. Агент/новые финансовые формулы/OCR/новые источники/прогнозы сюда не входят.

## Что измерить и решить

Записать точные версии Windows/CPU/RAM/runtime/GUI/renderer/build command и практический статус каждого кандидата. Сопоставимо измерить cold/warm startup, idle/peak memory, responsiveness/cancel, table interaction, PDF coordinates, UIA/DPI, размер собственного build artifact. Малый slice не является performance/quality всей будущей программы. Не обещать8/16/32GB минимумы по размеру весов.

ADR должен выбрать один основной UI либо честно оставить конкретный технический блокер. Оценить: reuse Python, доступность, Windows packaging, лицензии, сложность сопровождения одним пользователем+Codex. Qt предпочтителен, если проверка проходит; WPF — fallback при конкретной проблеме. Нельзя выбирать только по screenshot или популярности. WinUI/Tauri/Electron/pywebview не реализовывать параллельно без нового существенного основания.

Собственный code-license пока не выбран; не назначать её пользователю автоматически. Проверить Qt/PySide/LGPL module obligations и renderer separately; public Git не даёт права произвольно переупаковать PDF/weights. Выбор платного договора/сертификата не оформлять автоматически.
