# Продолжение: постоянный порядок сохранения проекта в GitHub

Пользователь09.11.2026 подтвердил постоянное правило: все следующие изменения сохранять через рабочую ветку, коммиты и pull request. Прочитай AGENTS.md, STATUS.md, docs/workflow.md и раздел «Постоянный порядок GitHub» в docs/github_collaboration.md. Затем выполняй только новую конкретную задачу пользователя.

Перед работой проверь status, текущую ветку и актуальную main. Изолируй задачу в отдельном рабочем дереве, если в исходной папке есть параллельные изменения. Сохраняй только относящиеся к задаче файлы. После результата выполни подходящие проверки, создай коммит, загрузи рабочую ветку и открой/обнови PR без повторного формального запроса на эти уже разрешённые действия.

Перед merge проверь актуальность базы, конфликты, diff, подходящие тесты и совместный сквозной путь. GitHub CI не объявляй подключённым без фактического workflow/результата. Прямой/force push в main, ослабление ruleset и обязательные одобрения других формальных участников исключены. Сливай PR по конкретному поручению или уже имеющемуся разрешению пользователя; не вводи новый круг подтверждения, если он уже пройден.

Стабильные этапы помечай тегами по результатам проверки; ошибочное слияние отменяй revert-PR. Не добавляй первичные PDF/страницы/полный текст/индекс, модели, бинарники и секреты. Не приписывай человеческую проверку, новые метрики или чужой вклад.

Текущие материалы КП3 могут оставаться локальными и не должны случайно войти в другую задачу. Для продолжения реализации используй актуальный план КП3 и prompts/kp3_01_product_scope_and_baseline.md, если пользователь поручил этот этап. Настройка GitHub Actions остаётся отдельной работой до её фактического выполнения. После этапа обнови статус, сохрани доказательства и самостоятельный промт; затем остановись.
